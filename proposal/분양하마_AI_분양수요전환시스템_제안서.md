# 제1장. 제안 요약

**헤드라인.** 본 제안의 요지는 광고 운영사를 교체하자는 것이 아니라, 분양 성과를 만드는 **업무의 범위 자체를 재정의**하자는 것입니다.

**[표 1-1] 장 요약**

| 구분 | 내용 |
|------|------|
| 문제 (Problem) | 시행사는 광고비를 집행하고도 "그 예산이 어떤 경로로 계약에 기여했는가"를 확인할 수 없다 |
| 원인 (Reason) | 분석·광고·현장 영업이 분리되어 있고, 광고대행의 업무 범위가 DB 전달에서 종료되도록 정의되어 있다 |
| 방법 (Method) | 현장분석부터 계약·학습까지 10단계를 단일 책임으로 운영하고, 예산 원장과 고객 원장을 같은 체계에 둔다 |
| 기대 효과 (Effect) | 예산 사용처와 고객 결과가 연결되어 검증되고, 부진의 원인(광고·가격·상담·수요)이 데이터로 구분된다 |

## 1.1 경영진께 드리는 요지

분양하마는 **광고를 대신 집행하는 회사가 아닙니다.** 현장의 가격과 입지에 대한 고객의 질문을 공식 데이터로 검증하고, 그 근거를 콘텐츠·광고·상담·방문·계약 관리까지 연결하여 **결과로부터 다시 배우는 운영체계를 제공하는 수요 전환 운영사**입니다.

당사가 하나의 체계로 통합하는 기능은 일곱 가지입니다.

|------|---------------------|

## 1.2 발주처가 직면한 문제

분양 성과는 더 이상 마케팅 부서의 성과 지표가 아니라 **사업 재무의 핵심 변수**입니다. PF 상환 일정과 분양 수입금 유입이 연동되어 있고, 분양 지연은 금융비용 증가, 추가 판촉비 투입, 조건 완화로 인한 수입 감소로 이어집니다.

그러나 다수의 현장에서 경영진이 확인할 수 있는 정보는 다음 수준에 머무릅니다.

**[표 1-3] 경영진이 받는 정보와 실제로 필요한 정보**

| 구분 | 현재 받는 정보 | 실제로 필요한 정보 |
|------|---------------|-------------------|
| 예산 | 견적서 총액, 세금계산서 | 매체별·일별 실제 집행액, 잔여 예산 |
| 유입 | 총 DB 건수, DB 단가 | 유효 DB, 소재별 유입 품질 |
| 현장 | 상담 건수 (구두 보고) | 미연락·연락지연 현황, 담당자별 처리 품질 |
| 성과 | 계약 건수 | 계약에 기여한 매체·소재·상담 경로 |
| 원인 | "시장이 어렵다" | 광고·가격·상담·수요 중 어느 것이 병목인가 |

우측 열의 정보가 없으면, 부진에 대한 대응은 추정에 의존하게 됩니다. 가격을 조정해야 할 국면에 판촉을 늘리거나, 상담을 교정해야 할 국면에 광고비를 증액하는 오판이 구조적으로 발생합니다.

## 1.3 구조의 차이

문제의 근원은 개별 업체의 역량이 아니라 **업무 범위의 정의**에 있습니다.

**[그림 1-1] 전통적 광고대행과 분양하마 운영체계의 업무 범위 대조**

```
[전통적 광고대행]

   광고 집행 ──→ DB 수집 ──→ DB 전달 ──→ 종료
       │
       └─ 업무 범위가 여기서 종료. 상담·방문·계약은 "현장의 일"로 분리


[분양하마 운영체계]

   ① 현장분석 → ② 판매논리 → ③ 콘텐츠 전략 → ④ 광고 집행
                                                    │
   ⑩ 최적화 ← ⑨ 학습 ← ⑧ 계약 ← ⑦ 방문 ← ⑥ 고객관리 ← ⑤ CRM 연동
       │
       └─ ⑩의 결과가 ①~④로 환류하여 다음 주기를 개선
```

전통적 대행 구조에서 광고 집행은 **업무의 전부**입니다. 분양하마 운영체계에서 광고 집행은 **열 단계 중 네 번째 단계**입니다. 광고 앞에는 팔릴 근거를 만드는 세 단계가, 광고 뒤에는 계약까지 관리하고 결과로부터 배우는 여섯 단계가 있습니다.

본 제안서 전체는 이 구조 차이가 어떻게 성과 차이로 이어지는지에 대한 설명입니다.

| 콘텐츠 제작비 | 운영수수료와 별도 견적 | 품목·수량·수정 횟수·납기·권리 |
| 분양 업무툴 | 운영기간 중 별도 라이선스비 없이 제공 (현장 1개) | 사용자 수, 보관 기간, 종료 후 처리 |

당사는 **10%라는 수수료율을 본 제안의 차별점으로 제시하지 않습니다.** 동일하거나 유사한 수수료 조건은 시장에도 존재합니다. 차별점은 같은 예산에서 다음 다섯 가지가 하나의 체계로 이어진다는 데 있습니다.

1. 근거가 검증된 현장분석
2. 매체별·일별 실집행 내역
3. 고객 처리 현황 (배정·연락·상담)
4. 방문·계약 결과와 기여 경로
5. 다음 캠페인의 개선 근거

## 1.6 의사결정자가 확인할 사항

**[표 1-6] 계약 전 확인 항목**

| 영역 | 확인 사항 | 미확정 시 영향 |
|------|-----------|----------------|
| 데이터 | 현장·분양·경쟁단지 자료와 외부 데이터의 이용 가능 여부 | 분석 범위 축소 또는 재설계 |
| 계정·정산 | 광고계정 소유·접근·결제 방식, 1+1 지원금의 정산 책임 | 실집행 검증 불가 |
| 개인정보 | 수집 동의문, 처리위탁, 보관기간, DB 이전 기준 | DB 연동 불가 |
| 제작 | 콘텐츠 수량·수정 횟수·촬영 범위, 정보 허브 운영기간 | 제작 착수 지연 |
| 현장 운영 | DB 배정·최초 연락 기준시간, 상담단계 정의, 등록 책임 | 광고-계약 연결 분석 제한 |
| 계약 | 성공 기준, 중단 조건, 변경관리, 종료 정산 기준 | 종료 시점 분쟁 소지 |

**분석 체계에 대해서는 다음 세 가지를 직접 요구하시기 바랍니다.** 제안서의 서술을 신뢰해 달라고 요청하는 대신, 확인 가능한 형태로 제출합니다.

**[표 1-6-1] 분석 체계에 대한 확인 요구 항목**

| 요구 항목 | 확인되는 것 |
|-----------|-------------|
| 커버리지표 (계약 전 제출) | 이 현장에서 15개 레이어 중 무엇이 확보되고 무엇이 안 되는가 — 실행 결과로부터 자동 생성되므로 운영 단계와 어긋나지 않음 |
| 근거원장이 포함된 샘플 리포트 | 각 수치가 어떤 데이터·규칙·표본에서 나왔는가, 그리고 **무엇이 미산출인가** |
| 예측 이력 장부 감사 결과 | 발행된 전망이 수정되지 않았음이 해시 재계산으로 확인되는가, 불변 장치가 실제로 작동하는가 |

## 1.7 성과에 대한 한계

본 제안은 분양계약 수, 가격 상승, 광고 수익률, AI 노출을 보장하지 않습니다(중요 전제 참조). 성과는 상품·가격·시장 국면·현장 인력·예산·기간의 영향을 함께 받습니다.

당사가 약속하는 것은 결과의 보장이 아니라, **결과가 만들어지는 전 과정을 측정 가능하고 확인 가능하게 운영하는 것**입니다. 수요 부족이 실제 원인인 현장에서는 그 사실을 데이터로 보고하고 조건 재검토를 안건화하는 것 역시 당사의 역할에 포함됩니다.

## 1.8 소결

본 장에서 제시한 세 가지 — 업무 범위의 재정의(1.3), 일곱 기능의 통합(1.4), 예산·고객 원장의 결합(1.5) — 이 본 제안의 골격입니다.

이어지는 제2장과 제3장은 현재의 구조가 왜 성과를 만들지 못하는지를 진단하고, 제4장 이후는 당사의 대안을 검증 가능한 형태로 기술합니다.

---

# 제2장. 분양 산업의 구조적 문제

**헤드라인.** 분양 운영의 핵심 문제는 시장 국면이 아니라, 성과를 확인할 수 없는 분업 구조에 있습니다.

**[표 2-1] 장 요약**

| 구분 | 내용 |
|------|------|
| 문제 (Problem) | 시행사는 "투자한 예산이 어떤 경로로 계약에 기여했는가"를 확인할 수 없다 |
| 원인 (Reason) | 분석·광고·현장 영업이 분업되어 관점·데이터·예산 정보가 주체별로 단절되어 있다 |
| 방법 (Method) | 구조를 네 개 단면(관점의 어긋남, 데이터 단절, 예산 불투명, 증빙 편향)으로 진단한다 |
| 기대 효과 (Effect) | 문제의 소재가 특정되고, 해결 수단이 갖춰야 할 요건(전 구간 연결)이 도출된다 |

## 2.1 진단의 출발점

시행사가 원하는 것은 광고 결과표가 아니라 **투자한 예산이 실제 매체, 고객 유입, 상담, 방문, 계약에 어떤 경로로 기여했는지의 확인**입니다. 다수 현장의 현실은 이와 다릅니다.

- 견적서와 세금계산서는 남지만, 매체별 실제 사용 금액과 광고계정 화면은 확인하기 어렵습니다.
- 광고 DB를 누가 언제 어떻게 처리했는지는 별도 보고를 요청해야만 확인됩니다.
- 계약이 발생해도 그 고객이 어떤 광고를 보고 들어왔는지 소급할 수 없습니다.

이 간극은 특정 업체의 불성실에서 발생하는 것이 아닙니다. 분석·광고·현장 영업이 분리된 구조에서 각 주체는 자기 영역을 성실히 수행하더라도, **영역 간 데이터가 연결되지 않으므로 전체 경로를 아는 주체가 존재하지 않습니다.**

## 2.2 단면 ① — 현장의 강점과 고객의 질문이 어긋나 있다

오늘의 수요자는 모델하우스 방문 전에 실거래가를 조회하고, 커뮤니티에서 경쟁 현장을 비교하며, 대출 한도를 계산한 상태로 도착합니다.

**[표 2-2] 현장이 말하는 것과 고객이 묻는 것**

| 현장이 말하는 것 | 고객이 실제로 묻는 것 |
|------------------|----------------------|
| 역세권·개발호재 | 실제로 어느 단계까지 진행됐고, 입주 시점에 체감 가능한가? |
| 특별혜택·계약조건 | 총취득원가는 얼마이며, 주변 대안보다 합리적인가? |
| 미래가치 | 상승 전제와 하락 위험을 함께 봤을 때 어떤 판단이 가능한가? |
| 입지 우수성 | 누가 실제로 유입될 수 있고, 생활권이 어떻게 달라지는가? |

판매 논리가 정리되지 않으면 광고는 혜택·호재·마감 문구를 반복하게 됩니다. 이 문구들은 **가격을 진지하게 검토하는 고객, 즉 계약에 가장 가까운 고객의 질문에 답하지 못합니다.**

## 2.3 단면 ② — 광고 데이터와 현장 영업 데이터가 끊겨 있다

**[표 2-3] 두 영역이 보유한 데이터**

| 광고 영역 | 현장 영업 영역 |
|-----------|----------------|
| 노출·클릭·DB 건수 | 연락 이력·상담 내용 |
| 캠페인·소재별 성과 | 고객 감도·거절 사유 |
| DB당 광고비 | 방문 예약·실제 방문 |
| 매체별 리드 | 계약 검토·계약 완료 |

두 데이터가 연결되지 않을 때 발생하는 손실은 세 가지입니다.

**첫째, 싼 DB와 방문 가능한 DB를 구분하지 못합니다.** DB 단가가 낮은 채널이 우수한 채널로 평가되지만, 그 DB가 상담·방문으로 이어지는지는 측정되지 않습니다.

**둘째, 광고비가 계약에 연결됐는지 확인할 수 없습니다.** 어떤 소재가 계약 고객을 유입시켰는지 모르므로, 잘된 것을 늘리고 안 된 것을 줄이는 기본적인 최적화가 불가능합니다.

**셋째, DB 처리 상태가 담당자 개인에게 귀속됩니다.** 엑셀·메신저로 전달된 이후 연락 누락과 지연이 관리 사각지대에서 발생하며, 인력 이탈 시 해당 고객군의 이력이 소멸합니다.

## 2.4 단면 ③ — 광고비의 사용처가 검증되지 않는다

예산 불투명성은 독립적인 구조 문제입니다.

**[표 2-4] 예산 통제가 어려운 지점**

| 지점 | 현상 |
|------|------|
| 실집행 확인 | 견적서·세금계산서만 발행되고 실제 매체 집행 내역은 확인 곤란 |
| 비용 구분 | 광고비·대행수수료·콘텐츠 제작비가 한 금액으로 제시되어 동일 조건 비교 불가 |
| 계정 접근 | 광고계정 접근 권한이 제공되지 않거나 가공된 결과 리포트만 전달 |
| 집행 추적 | 캠페인별 기간, 일별 사용액, 충전 내역, 잔여 예산의 확인 곤란 |
| 견적-실집행 차이 | 견적 금액과 실제 매체 집행 금액 사이의 차이 발생 가능 |

**1+1 광고비 지원 구조**에서는 이 문제가 증폭됩니다. 직원·팀이 광고비를 부담하면 현장·본부가 동액을 지원하는 방식은 현장 참여를 높이는 장점이 있으나, 부담금과 지원금, 수수료, 제작비, 실집행액이 한 견적서에 혼재되면 정산 통제가 약해집니다.

문제의 본질은 지원 제도 자체가 아니라 **"누가 부담했고, 어떤 매체에 언제 얼마가 집행됐으며, 잔액이 어떻게 처리됐는가"가 추적되지 않는다는 점**입니다.

## 2.5 단면 ④ — 증빙 편향이 예산 배분을 왜곡한다

발송 건수 확인이 쉬운 매체에 예산이 집중되는 현상이 관찰됩니다. LMS는 발송량과 단가가 명확히 증빙되므로 예산 소진과 보고에 유리하지만, 그 발송이 상담 연결·방문·계약으로 이어졌는지는 별도로 측정되지 않습니다.

그 결과 운영 목표가 **신규 수요 발굴에서 단기 증빙 확보로 이동**합니다. 이는 개별 담당자의 판단 오류가 아니라, 증빙 가능한 것만 평가되는 구조가 유도하는 결과입니다.

## 2.6 소결

현장에서 필요한 증빙은 견적서가 아닙니다. **실제로 어느 매체에 얼마가 사용됐고, 어떤 고객이 유입됐으며, 그 고객이 상담·방문·계약으로 어떻게 이동했는지**를 확인할 수 있어야 합니다.

이 확인이 가능한 구조와 불가능한 구조의 차이가, 제3장에서 다룰 광고 실패 사이클의 원인입니다.

---

# 제3장. 기존 분양광고가 실패하는 이유

**헤드라인.** 광고는 소재나 매체에서가 아니라, 광고의 앞(근거)과 뒤(전환·학습)에서 실패합니다.

**[표 3-1] 장 요약**

| 구분 | 내용 |
|------|------|
| 문제 (Problem) | 예산을 증액하고 소재를 교체해도 계약이 늘지 않는다 |
| 원인 (Reason) | 광고 전 근거 부재 → 광고 중 지표 오류 → 광고 후 데이터 단절 → 학습 부재의 4단계 사이클이 반복된다 |
| 방법 (Method) | 실패 지점을 단계별로 분해하고, 원인(광고·가격·상담·수요)을 구분할 데이터 요건을 정의한다 |
| 기대 효과 (Effect) | 부분 교체가 아니라 전 구간 연결이 필요하다는 해법의 요건이 확정된다 |

## 3.1 4단계 실패 사이클

**[표 3-2] 단계별 실패 양상**

| 단계 | 실패 양상 | 결과 |
|------|-----------|------|
| ① 광고 전 | 팔릴 근거가 정리되지 않음. 현장분석이 기본 분양정보 확인 수준 | 광고 문구가 혜택·입지·마감의 반복으로 수렴 |
| ② 광고 중 | 클릭과 DB 단가만 평가. 방문·계약 가능성과 무관한 지표로 운영 | 저의도 유입 증가, 현장 상담 인력 소모 |
| ③ 광고 후 | 상담·방문·계약과 분리. 광고의 책임이 DB 전달에서 종료 | 어떤 근거가 통했는지 확인 불가 |
| ④ 다음 캠페인 | 실패 원인을 모른 채 반복. 소재 교체가 유일한 개선 수단 | 동일한 문제가 재발 |

## 3.2 실패는 업무 범위 정의의 구조적 귀결이다

**[그림 3-1] 전통적 대행의 업무 범위와 실패 지점의 대응**

```
전통적 대행의 업무 범위:  광고 집행 → DB 수집 → DB 전달 → 종료

구조적으로 비어 있는 구간:
   [광고 전]  근거를 검증하는 단계가 없음        → 실패 ①
   [광고 중]  평가 기준이 DB 수량·단가뿐          → 실패 ②
   [광고 후]  전달 이후의 책임과 데이터가 없음     → 실패 ③
   [다음 주기] 결과 데이터가 없어 학습이 불가능     → 실패 ④
```

대행사가 불성실해서가 아니라, **업무 범위가 DB 전달에서 종료되도록 정의되어 있기 때문에** 네 가지 실패가 반복됩니다. 이 점이 본 제안의 출발점입니다. 문제는 수행 품질이 아니라 범위 설계에 있습니다.

## 3.3 근거 없는 메시지의 이중 비용

광고 전 단계의 실패(①)는 두 번 비용을 발생시킵니다.

**[표 3-3] 근거 부재가 발생시키는 비용**

| 발생 시점 | 비용 |
|-----------|------|
| 광고 단계 | 반대근거를 다루지 않은 혜택·호재 중심 문구는 가격 저항을 해소하지 못해 유효 수요를 놓침 |
| 상담 단계 | 광고에서 형성된 기대와 현실의 격차가 확인되면서 신뢰가 훼손됨. 손실이 개별 계약을 넘어 현장 평판으로 확산 |

## 3.4 잘못된 평가 지표의 유도 효과

지표는 행동을 유도합니다. DB 단가로 평가받는 운영자는 DB 단가를 낮추는 방향으로 움직입니다.

**[표 3-4] DB 단가 중심 평가가 유도하는 결과**

| 운영자의 합리적 대응 | 발생하는 결과 |
|---------------------|---------------|
| 경품·이벤트성 유입 확대 | DB 수량 증가, 유효 DB 비율 하락 |
| 저의도 광범위 타깃 확대 | 상담 인력의 응대 시간 소모 |
| 고의도 검색 수요 축소 | DB 단가는 높지만 계약 기여가 큰 채널이 감액됨 |

평가 지표가 계약과 연결되어 있지 않으면, **성실한 운영조차 잘못된 방향으로 최적화됩니다.**

## 3.5 최종적 실패 — 원인을 구분할 수 없다

부진 현장에서 물어야 할 질문은 네 가지입니다. **광고의 문제인가, 가격의 문제인가, 상담의 문제인가, 수요 자체의 문제인가.**

4단계 실패 사이클 안에서는 이 질문에 답할 데이터가 존재하지 않습니다. 그 결과 대응은 추정에 의존하게 되고, 가격을 조정해야 할 국면에 판촉을 늘리거나 상담을 교정해야 할 국면에 광고비를 증액하는 오판이 발생합니다.

여기서 한 가지를 분명히 합니다. **수요 부족이 실제 원인인 현장도 존재합니다.** 모든 부진이 광고나 운영으로 해결되지는 않습니다. 핵심은 원인을 감(感)으로 판단하지 않는 것입니다. 원인이 데이터로 구분되어야 해결 가능한 문제에 예산을 투입하고, 해결 불가능한 문제에는 조건 재검토라는 다른 대응을 선택할 수 있습니다.

## 3.6 소결

실패 사슬의 어느 한 고리만 교체하는 것 — 광고대행사 교체, CRM 단독 도입, 분석 리포트 단독 구매 — 으로는 사슬이 끊어지지 않습니다.

필요한 것은 **분석부터 계약 데이터까지 전 구간을 하나의 체계로 연결하는 운영자**입니다. 그 정의와 작동 방식이 제4장의 주제입니다.

# 제4장. 분양하마 운영 방법론

**헤드라인.** 분양하마는 광고대행사가 아니라, 10단계 가치 사슬을 단일 책임으로 운영하고 결과를 다음 주기에 환류시키는 수요 전환 시스템 운영사입니다.

**[표 4-1] 장 요약**

| 구분 | 내용 |
|------|------|
| 문제 (Problem) | 실패 사이클(제3장)은 어느 한 기능의 교체로는 끊어지지 않는다 |
| 원인 (Reason) | 분업 구조의 업체는 자기 구간만 책임지므로, 구간 간 연결이 발생하지 않는다 |
| 방법 (Method) | 현장분석부터 최적화까지 10단계를 단일 책임으로 운영하고, 7단계 내부 운영 표준으로 실행한다 |
| 기대 효과 (Effect) | 매주 검증된 지식이 축적되고, 발주처는 수수료율이 아닌 시스템 기준으로 평가할 수 있다 |

## 4.1 운영체계의 정의

분양하마 AI 분양 수요 전환 시스템은 하나의 광고 매체도, 하나의 분석 리포트도, 하나의 소프트웨어도 아닙니다. 다음의 순환을 단일 책임으로 운영하는 체계입니다.

> 현장 자료와 공식 데이터를 검증하여 가격·수요·공급·촉매·위험을 분석하고, 이를 판매 논리와 고객 질문형 콘텐츠로 전환한 뒤, 고객 단계별로 광고를 집행하고, 유입 고객을 업무툴에서 배정부터 계약까지 관리하며, 그 결과를 다시 분석과 광고 최적화에 반영한다.

## 4.2 10단계 가치 사슬

**[표 4-2] 단계별 업무 범위 대조**

| 단계 | 전통적 대행 | 분양하마 | 상세 |
|------|------------|----------|------|
| ① 현장분석 | 없음 (기본 분양정보 확인) | 7대 카테고리·15개 레이어·300+ 지표 검증 | 제5장 |
| ② 판매 논리 | 없음 | 고객 질문 6축 메시지맵, 표현 등급 지정 | 제6장 |
| ③ 콘텐츠 전략 | 범용 이미지·이벤트 소재 | 질문형 콘텐츠, 검증형 정보 허브 | 제7장 |
| ④ 광고 집행 | **업무의 전부** | **10단계 중 하나** | 제8장 |
| ⑤ CRM 연동 | DB 전달 후 종료 | 자동 연동, 규칙 기반 배정 | 제9장 |
| ⑥ 고객관리 | 없음 (현장의 일) | 10단계 상태 관리, 연락지연 통제 | 제9장 |
| ⑦ 방문 | 없음 | 예약·이행·노쇼 관리 | 제9장 |
| ⑧ 계약 | 없음 | 계약 검토 관리, 기여 경로 기록 | 제9·10장 |
| ⑨ 학습 | 없음 | 거절·전환 원인 분석 | 제10장 |
| ⑩ 최적화 | 소재 교체 수준 | 예산·메시지·상담의 재조정 | 제10·12장 |

좌측 열의 "없음"은 개별 업체의 불성실이 아니라 **업무 범위 정의의 차이**입니다. 분업 구조에서 각 주체는 관행상 성실히 수행하더라도 항목 간 연결이 발생하지 않으며, 연결이 없는 한 개별 항목을 개선해도 제3장의 실패 사슬은 끊어지지 않습니다.

*본 대조는 특정 업체를 일반화한 비교가 아니라, 운영 구조(업무 범위 정의)의 차이를 설명하기 위한 것입니다.*

## 4.3 7단계 내부 운영 표준

10단계 가치 사슬은 발주처·고객 관점의 흐름이며, 이를 실행하는 내부 운영은 일곱 단계로 표준화됩니다.

**[표 4-3] 7단계 전환 운영과 생성 정보**

| 내부 단계 | 담당하는 가치 사슬 | 핵심 활동 | 생성되는 관리 정보 |
|-----------|-------------------|-----------|-------------------|
| ① 진단 | ① 현장분석 | 자료 수령, 데이터 커버리지 점검 | 입력검증표, 분석경계, 결측·제약 |
| ② 분석 | ① 현장분석 | 가격·수요·공급·환금성·촉매·위험 분석 | 근거원장, 현장진단, 시나리오 |
| ③ 설득설계 | ② 판매 논리 | 고객 질문·가격저항·반대근거 정리 | 메시지맵, 고객유형, 표현등급 |
| ④ 제작 | ③ 콘텐츠 전략 | 정보 허브·리포트·소재 제작 | 소재목록, 버전, 승인기록 |
| ⑤ 집행 | ④ 광고 | 매체별 역할 운영 | 캠페인·지출·노출·클릭·전환 |
| ⑥ 전환관리 | ⑤~⑧ CRM~계약 | 배정·연락·상담·방문·계약 관리 | 고객상태, 처리시간, 거절사유 |
| ⑦ 학습 | ⑨~⑩ 학습·최적화 | 광고 성과와 현장 성과의 결합 분석 | 기여소재, 병목, 개선안 |

## 4.4 폐쇄형 학습 구조

일곱 번째 단계가 첫 번째 단계로 되돌아가는 것이 이 체계의 핵심입니다.

광고 데이터만으로는 고객이 왜 거절했는지 알 수 없고, 상담 기록만으로는 어떤 광고가 그 고객을 유입시켰는지 알 수 없습니다. 당사는 광고 소재, 유입 캠페인, 담당자, 최초 연락 시각, 상담 결과, 방문, 계약 상태를 하나의 키로 연결합니다.

**[그림 4-1] 운영 순환**

```
광고 소재 → 광고비 → 고객 유입 → 담당자 배정 → 최초 연락 → 상담 → 방문 → 계약
                                                                          │
   ┌──────────────────────────────────────────────────────────────────────┘
   ▼
거절·성공 원인 분석 → 메시지·매체·상담 개선 → (다음 주기의 광고 소재)
```

이 순환이 작동하는 조직과 작동하지 않는 조직의 차이는 시간이 지날수록 확대됩니다. 작동하는 조직은 매주 검증된 지식을 축적하고, 작동하지 않는 조직은 매주 같은 실험을 반복합니다.

## 4.5 수행 주체 구조

**[표 4-4] 분양하마와 테이블플립의 역할**

| 주체 | 역할 |
|------|------|
| 분양하마 | 제안·계약·현장분석·설득설계·광고 운영·현장 전환관리·성과 보고의 수행 주체 |
| 테이블플립 (모회사) | AI·데이터 분석·GEO·업무시스템의 기술 기반 제공 |

분양하마는 테이블플립의 분석·콘텐츠·디지털 운영 역량을 분양 업무에 결합한 자회사이자 전문 운영 브랜드입니다. 기술 기반은 모회사의 축적된 역량을 활용하되, **분양 현장의 계약·운영·책임은 분양하마가 단일 창구로 담당합니다.**

## 4.6 "수수료 10%"를 차별점으로 제시하지 않는 이유

당사의 표준 운영수수료는 광고운영예산의 10%입니다. 그러나 이 수치는 시장에서도 확인될 수 있는 조건이므로, 본 제안의 차별점으로 제시하지 않습니다.

**[표 4-5] 수수료 비교 시 확인해야 할 구조**

| 판단 항목 | 수수료율만 확인할 때 | 구조까지 확인할 때 |
|-----------|---------------------|-------------------|
| 기준 금액 | "10%"라는 숫자만 비교 | VAT 포함 여부, 제작비 포함 여부, 최소 비용 |
| 실제 매체비 | 나머지가 모두 광고비라고 추정 | 충전·결제·환불·잔액까지 실집행 원장으로 확인 |
| 제공 업무 | 운영 범위를 포괄적으로 이해 | 분석·전략·세팅·최적화·리포트의 실제 수행 범위 |
| 콘텐츠 | 운영비에 포함된 것으로 오해 | 종류·수량·촬영·수정·소유권을 별도 견적으로 확정 |
| 성과 | DB 단가 중심 비교 | 유효 DB·상담·방문·계약·거절사유까지 기준 통일 |

발주처께 요청드리는 것은 분양하마를 포함한 모든 제안사를 **이 구조 기준으로 비교**해 주시는 것입니다.

## 4.7 인접 서비스와의 위치 비교

프롭테크 시장에는 당사와 부분적으로 겹치는 서비스 유형이 존재합니다. 발주처의 정확한 판단을 위해 유형별 차이를 명시합니다.

**[표 4-6] 인접 서비스 유형과 분양하마의 위치**

| 서비스 유형 | 제공 범위 | 강점 | 업무의 종료 지점 | 분양하마와의 관계 |
|-------------|-----------|------|------------------|-------------------|
| AI 분양가 산정·시장분석 솔루션 | 적정 분양가 산정, 청약 수요 예측, 사업지 분석 리포트, 데이터룸 | 대량 데이터 기반 신속한 사업성 판단 | **분석 리포트 납품에서 종료** | 분석까지는 유사. 분석을 광고·상담·계약 전환으로 실행하는 운영이 없음 |
| 분양가 보장형 금융 상품 | 세대 단위 적정가 산출, 보호약정(환매권 등), 위험 조기경보 | 수요자 심리 방어, 금융 구조 설계 | **보장 상품 판매에서 종료** | 수요자 안심 장치로서 당사 운영과 병행 가능. 수요를 발굴·전환하는 기능이 없음 |
| 광고대행 | 매체 집행, 소재 제작, DB 수집 | 매체 운영 실무 | **DB 전달에서 종료** (제3장) | 당사 10단계 중 ④ 한 단계에 해당 |
| **분양하마** | 현장분석 → 판매 논리 → 콘텐츠 → 광고 → CRM → 고객관리 → 방문 → 계약 → 학습 → 최적화 | **전 구간의 단일 책임 운영** | 계약·학습·다음 주기 최적화까지 | — |

*본 비교는 특정 업체가 아닌 서비스 유형 단위의 비교이며, 각 유형의 서비스는 고유한 가치를 갖습니다.*

세 유형과 당사의 차이는 우열이 아니라 **업무의 종료 지점**입니다. 분석 솔루션은 리포트에서, 보장 상품은 약정 체결에서, 광고대행은 DB 전달에서 업무가 종료됩니다. 당사는 분석 결과가 광고 문구가 되고, 광고 유입이 상담 기록이 되고, 거절 사유가 다음 분석의 입력이 되는 **전환 운영의 전 구간**을 담당합니다. 발주처가 이미 분석 솔루션이나 보장 상품을 이용 중이라면, 당사 운영체계는 이를 대체하는 것이 아니라 그 산출물이 실제 계약으로 전환되는 구간을 담당합니다.

## 4.8 소결

분양하마의 경쟁력은 개별 기능이 아니라 기능 간의 연결 구조에 있습니다.

이 구조의 앞단, 즉 **팔릴 근거를 생산하는 방법론**이 제5장의 주제입니다. 본 제안서에서 가장 상세히 기술하는 장이며, 당사가 광고대행과 구분되는 가장 근본적인 지점이기도 합니다.

# 제5장. AI 현장가치 분석

**헤드라인.** 분양하마는 아파트 가격을 비교하지 않습니다. **7대 코어 카테고리 → 15개 데이터 레이어 → 300개 이상의 표준 지표**로 구성된 프레임워크에서, 서로 독립적인 데이터셋으로 현장가치를 교차 검증합니다.

**[표 5-1] 장 요약**

| 구분 | 내용 |
|------|------|
| 문제 (Problem) | 주변 시세를 비교해 가격을 추정하는 보고서는 순환 논리·오염된 표본·단일 소스 의존의 결함을 갖는다 |
| 원인 (Reason) | 현장가치는 직접 관측할 수 없는 변수이므로, 단일 데이터로는 신뢰할 수 있게 추정되지 않는다 |
| 방법 (Method) | 3층 프레임워크(5.2~5.3)에 방법론 엔진 6종 — GIS 공간분석·시계열·교차검증·반대근거·신뢰도 평가·조정계수 교정(5.4) — 를 적용한다 |
| 기대 효과 (Effect) | 반증을 통과한 판매 근거가 확보되고, 4개 독립 판정(5.8)이 판매 전략의 형태를 결정한다 |

분석에서 AI가 담당하는 범위와 사람의 책임은 5.9에서 한 번에 정의합니다.

## 5.1 분석 철학 — 가격 비교가 아니라 가치의 독립 검증

### 5.1.1 통상적 시세 비교 보고서의 세 가지 결함

**[표 5-2] 시세 비교 방식의 방법론적 결함**

| 결함 | 내용 | 결과 |
|------|------|------|
| 순환 논리 | 가격을 가격으로 설명. "주변이 이 가격이니 이 현장도 이 가격" | 주변 가격이 유지될 근거가 검증되지 않아, 시장 하강 국면에서 논리가 성립하지 않음 |
| 오염된 표본 | 호가·취소 거래·이상 고가·특수관계 거래가 정제되지 않음 | 비교 기준 자체가 왜곡됨 |
| 단일 소스 의존 | 하나의 데이터셋에서 결론 도출 | 해당 데이터의 오류·편향·공백을 결론이 그대로 승계함 |

### 5.1.2 대안 — 독립 데이터셋에 의한 삼각측량

현장의 가치는 직접 관측할 수 없는 잠재 변수입니다. 따라서 **생성 주체와 수집 경로가 서로 다른 여러 데이터셋으로 같은 대상을 측정하는 방식**으로만 신뢰할 수 있게 추정됩니다.

**[표 5-3] 검증 대상별 독립 측정 데이터**

| 검증 대상 | 독립 측정 데이터 | 담당 카테고리 |
|-----------|------------------|---------------|
| 거주 수요의 존재 | 인구·가구 데이터 | C1 |
| 수요의 지불 능력 | 고용·소득 데이터 | C2 |
| 생활권의 활력 | 유동·소비 데이터 | C3·C4 |
| 시장의 실제 움직임 | 정제된 거래 데이터 | C5 |
| 미래의 경쟁 부담 | 공급·계획 데이터 | C6·C7 |

### 5.1.3 세 가지 운영 원칙

**[표 5-4] 분석 운영 원칙**

| 원칙 | 내용 |
|------|------|
| 독립성 (Independence) | 결론을 지지하는 근거는 생성 주체와 수집 경로가 서로 다른 데이터셋에서 나와야 한다 |
| 수렴 (Convergence) | 서로 다른 데이터가 같은 방향을 가리킬 때만 판매 근거로 채택한다 |
| 반증 (Falsification) | 결론을 약화하는 데이터를 먼저 탐색하고, 그것을 통과한 설명만 남긴다 |

## 5.2 프레임워크 구조 — 7 → 15 → 300+

**[그림 5-1] 3층 분석 프레임워크**

```
┌───────────────────────────────────────────────────────────┐
│              7대 코어 카테고리 (Core Categories)             │  ← 결론의 단위
│   인구·가구 │ 고용·소득 │ 이동·교통 │ 상권·소비                │    "수요가 있는가?"
│   주택시장 │ 공급 │ 개발·도시계획                              │
└──────────────────────────┬────────────────────────────────┘
                           ▼
┌───────────────────────────────────────────────────────────┐
│              15개 데이터 레이어 (Data Layers)                │  ← 독립성의 단위
│   L1 상주인구 · L2 가구수요 · L3 인구이동                     │    "무엇으로 측정하는가?"
│   L4 고용 · L5 소득 · L6 유동인구 · L7 생활이동 · L8 교통망     │
│   L9 상권 · L10 카드소비 · L11 실거래 · L12 청약/미분양        │
│   L13 공급 파이프라인 · L14 개발계획 · L15 도시계획            │
└──────────────────────────┬────────────────────────────────┘
                           ▼
┌───────────────────────────────────────────────────────────┐
│            300+ 표준 분석 지표 (Indicators)                  │  ← 재현성의 단위
│   지표별 정의 · 산식 · 공간단위 · 출처 · 갱신주기 · 신뢰등급     │    "어떻게 계산하는가?"
└───────────────────────────────────────────────────────────┘
```

**[표 5-5] 각 층의 역할**

| 층 | 단위 | 역할 |
|----|------|------|
| 카테고리 | 결론 | 최종 판정(5.8)이 내려지는 단위. 경영진 보고와 고객 설득 논리(제6장)의 구성 단위 |
| 레이어 | 독립성 | 생성 주체·수집 경로가 구분되는 데이터셋. 교차검증(5.4.3)이 수행되는 단위 |
| 지표 | 재현성 | 정의·산식·공간단위·출처·갱신주기·신뢰등급이 등록되어, 누가 계산해도 같은 값이 산출되는 단위 |

표준 지표 사전은 300개 이상의 지표로 구성됩니다. 다만 다음을 명시합니다. **현장별로 실제 적용되는 지표 수는 데이터 커버리지(5.10)에 따라 달라지며, 계약 전에 커버리지표로 확정하여 제출합니다.** 지표 수는 과시의 대상이 아니라 관리의 대상입니다.

## 5.3 7대 코어 카테고리와 15개 데이터 레이어

### 5.3.1 전체 구성

**[표 5-6] 카테고리·레이어·지표 구성**

| 카테고리 | 답하는 질문 | 데이터 레이어 | 표준 지표 (예시 수) |
|----------|------------|---------------|--------------------|
| C1. 인구·가구 기반 | 실제 거주 수요가 형성·유지되는가? | L1 상주인구·인구구조 / L2 가구·주거수요 / L3 인구이동 | 약 60개 |
| C2. 고용·소득 기반 | 배후 수요와 구매력이 뒷받침되는가? | L4 사업체·고용 / L5 소득·구매력 | 약 40개 |
| C3. 이동·교통 | 사람의 흐름과 접근성이 경쟁력 있는가? | L6 유동인구 / L7 생활이동·O/D / L8 교통망·접근성 | 약 60개 |
| C4. 상권·소비 | 생활권이 소비를 지탱할 만큼 성숙한가? | L9 상권 활동 / L10 카드소비 | 약 35개 |
| C5. 주택시장 | 호가가 아닌 시장가격은 어떻게 움직이는가? | L11 매매·전월세 실거래 / L12 청약·미분양 | 약 45개 |
| C6. 공급 | 희소성인가, 공급 부담인가? | L13 공급 파이프라인 | 약 25개 |
| C7. 개발·도시계획 | 가치를 바꿀 계획이 실제로 진행되는가? | L14 개발계획·공공투자 / L15 도시계획·토지이용 | 약 40개 |

*지표 수는 표준 지표 사전 기준의 근사치이며, 현장 적용 수는 커버리지 확정 후 결정됩니다.*

### 5.3.2 C1. 인구·가구 기반 — 거주 수요의 검증

**L1 상주인구·인구구조 (Demographic Analysis)**

생활권 내 실제 거주 인구의 규모와 구조를 격자·집계구 단위로 분석합니다. 시·구 평균에 가려진 생활권 단위의 실제 인구 동태를 확인하는 것이 목적입니다.

| 대표 지표 |
|-----------|
| 생활권 상주인구와 다년 증감률 / 연령대별 구성과 핵심 수요 연령(30~40대) 비중 / 생산가능인구 비율 / 고령화 속도 / 인구 피라미드의 형태 변화 / 세대당 인구 |

**L2 가구·주거수요 (Household Demand)**

주택을 구매하는 단위는 개인이 아니라 가구입니다. 현장의 평형 구성이 생활권의 가구 구조와 정합하는지를 검증합니다.

| 대표 지표 |
|-----------|
| 가구수 증감 / 가구 유형(1인·신혼·유자녀·고령) 구성 / 평균 가구원수 추이 / 주택 점유형태(자가·전세·월세) 분포 / 주택 유형별 거주 현황 / 가구 분화 속도 |

*검증 예시:* 중대형 중심 현장의 생활권에서 1인 가구만 증가하고 있다면, 평형 구성과 수요 구조의 불일치를 조기에 확인할 수 있습니다.

**L3 인구이동 (Migration)**

| 대표 지표 |
|-----------|
| 전입·전출 순이동 / 연령대별 이동 방향 / 유입 상위 출발지 / 유출 상위 목적지 / 시점별 이동 추세 |

*활용:* "어디에서 누가 들어오고 있는가"는 광고 타깃 지역 설계(제8장)의 직접적 입력값이 됩니다.

*교차검증:* 통계상 유입 출발지 구성은 **현장 방문객의 실제 거주지 분포(제9장 CRM에서 축적)와 대조**됩니다. 통계상 유입이 거의 없는 지역에서 방문객이 몰린다면 수요 가정이 틀렸거나 광고 타깃이 실제 수요와 어긋난 것이므로, 어느 쪽이든 재검토 대상으로 지정됩니다(5.11.3).

### 5.3.3 C2. 고용·소득 기반 — 배후 수요와 구매력의 검증

**L4 사업체·고용 (Employment Demand)**

직주근접은 분양 설득의 핵심 논리이지만, 검증 없이 사용되면 가장 쉽게 반박되는 논리이기도 합니다.

| 대표 지표 |
|-----------|
| 시간권 내 사업체 수·종사자 수와 증감 / 산업 대분류별 고용 구성 / 주간인구 대 야간인구 비율 / 고용 밀도 / 대규모 사업장·산업단지의 고용 규모와 통근권 |

*서술 원칙:* "일자리가 많다"가 아니라 **"현장에서 몇 분 시간권에, 어떤 산업의, 몇 명의 고용이, 어떤 추세로 존재한다"**로 답합니다.

**L5 소득·구매력 (Income)**

수요는 의사만으로 성립하지 않고 지불 능력으로 완성됩니다.

| 대표 지표 |
|-----------|
| 생활권·통근권 가구소득 분포 / 소득 구간별 가구 비중 / 주택구매력 추정(소득 대비 총취득원가 배수) / 대출 여력과 금리 민감도 / 전세 보증금 수준 |

*활용:* 분양가가 형성된 시장의 구매력 범위 안에 있는지를 판정하며, 가격 저항(제6장)의 구조적 원인을 이 레이어에서 확인합니다.

*가정과 실측의 분리:* 공개 통계가 제공하는 것은 평균·중위 같은 대표값이지 가구별 분포가 아닙니다. 당사는 **분포의 중심값을 시군구 실측 중위소득으로 고정**하고, 분포의 형태(로그정규 근사)와 산포는 가정으로 남긴 뒤 그 사실을 리포트에 병기합니다. "전부 가정"과 "형태만 가정"은 다른 상태이며, 그 차이를 발주처가 구분할 수 있어야 합니다.

### 5.3.4 C3. 이동·교통 — 흐름과 접근성의 검증

**L6 유동인구 (Floating Population)**

| 대표 지표 |
|-----------|
| 시간대별·요일별 유동량 / 주중·주말 패턴 / 체류형 대 통과형 비율 / 유동 발생 목적지(상업·업무·교육) 분포 / 시간당 평균 체류 인구 |

*정제 원칙:* 통과 인구를 생활권 활력으로 오독하지 않도록 체류·통과를 분리하고, 표본·중복 단말 보정을 적용합니다. 민간 모바일 유동 데이터는 라이선스 확인 후 적용하며, 미확보 시 공공 대체 지표와 그 한계를 명시합니다(5.10).

**L7 생활이동·O/D (Mobility)**

| 대표 지표 |
|-----------|
| 출발지-도착지(O/D) 통행량 / 통근·통학 흐름의 방향과 규모 / 생활권 간 이동 의존도 / 대중교통 대 승용차 수단 분담률 |

*활용:* 현장이 사람들의 실제 동선 위에 있는지, 동선 밖에 있는지를 데이터로 확인합니다.

**L8 교통망·접근성 (Transportation)**

| 대표 지표 |
|-----------|
| 도보·차량·대중교통별 실제 이동시간(네트워크 기준) / 주요 고용 중심지·생활 거점까지의 소요시간 / 역·정류장 접근성 / 도로 위계와 혼잡도 / 개통 예정 노선 반영 전후의 접근성 변화 시뮬레이션 |

*통제 원칙:* "역세권" 표현은 이 레이어의 계산 결과가 뒷받침할 때만 사용 가능 등급(14.5)을 받습니다. 통제는 사후 검수가 아니라 **문장 생성 단계**에서 이루어집니다 — 최근접역이 보행 보정 기준 도보 10분 이내일 때만 "도보 n분" 문장이 만들어지고, 그 밖에는 문장 자체가 생성되지 않으며 리포트에 실측 직선거리와 함께 "역세권 표현 사용 불가"가 기재됩니다. 현장이 접근성을 주장하려면 좌표가 먼저 그것을 지지해야 합니다.

### 5.3.5 C4. 상권·소비 — 생활권 성숙도의 검증

**L9 상권 활동 (Commercial Activity)**

| 대표 지표 |
|-----------|
| 업종별 점포 수와 구성 / 개업·폐업률과 생존율 / 프랜차이즈 침투율 / 공실 추정 / 생활 필수 업종(식료품·의료·교육)의 충족도 |

*판정 원칙:* 폐업률이 상승하는 상권과 신규 개업이 지속되는 상권은 동일한 "상권 발달"로 분류할 수 없습니다.

**L10 카드소비 (Card Spending)**

| 대표 지표 |
|-----------|
| 업종별 카드 매출 규모와 증감 / 소비 시간대 분포 / 거주자 소비 대 유입 소비 비율 / 객단가 추이 |

*적용 조건:* 익명 카드소비 데이터는 별도 협의·라이선스 대상입니다(5.10). 확보 시 상권의 실제 자금 흐름을, 미확보 시 공공 상권 데이터 기반의 대체 분석과 그 한계를 명시합니다.

### 5.3.6 C5. 주택시장 — 시장 신호의 검증

**L11 매매·전월세 실거래 (Housing Transactions)**

| 대표 지표 |
|-----------|
| 정제된 실거래가와 추세(취소·중복·이상·특수관계 거래 제거 후) / 거래량과 거래 회전율 / 전세가와 전세가율 / 월세 전환 추이 / 매도 소요기간 추정 / 단지 내 가격 분산 / 시장 지수 대비 초과·미달 성과 / **분양권·입주권 실거래와 프리미엄 추이** / **매물량 증감과 호가-실거래 갭** |

*분석 원칙:* 호가가 아니라 체결가가, 한 건이 아니라 분포가 분석 대상입니다. 두 가지를 보완적으로 사용합니다. 첫째, **신축 분양 현장의 우선 비교군은 구축 아파트가 아니라 인근 분양권·입주권 실거래**입니다 — 상품 연식·조건이 가장 유사한 시장 신호이기 때문입니다. 둘째, 실거래는 후행 지표이므로 **매물량 증감과 호가-실거래 갭을 선행 신호**로 함께 추적하여 시장 전환을 조기에 포착합니다(조기경보 체계 5.11.2와 연결).

**L12 청약·미분양 (Unsold Inventory)**

| 대표 지표 |
|-----------|
| 인근 청약 경쟁률과 미달 이력 / 가점 커트라인 추이 / 미분양 재고와 소진 속도 / 준공 후 미분양 비율 / 계약 해지율 / 청약 신청자의 거주지 분포 |

*교차 활용:* 미분양은 공급 과잉의 후행 증거이자 수요 한계의 직접 증거이므로, C6 공급 분석과 반드시 교차검증됩니다. 최근 6개월 미분양이 20% 이상 증가하면, 확률조정 공급 부담이 낮게 산출되더라도 공급 판정(5.8 ③)을 위험 방향으로 상향합니다.

### 5.3.7 C6. 공급 — 경쟁 물량의 검증

**L13 공급 파이프라인 (Supply Pipeline)**

| 대표 지표 |
|-----------|
| 인허가·착공·분양·입주예정 물량의 단계별 집계 / 시기별 입주 집중도 / 경쟁 시장권 내 동일 상품 유형 물량 / 확률조정 공급 / 정비사업 진행 물량 |

*산출 방식:* 발표된 모든 세대를 동일하게 합산하지 않습니다.

> **확률조정 공급 = Σ (각 공급 물량 × 해당 단계에서 실제 입주 기간 내에 실현될 가능성)**

공급은 현장의 가격·판촉 전략에 시한을 부여하는 변수이므로, 물량의 총량보다 **시기 축**이 중요합니다.

*목록의 검증:* 공급 목록이 수기 입력에만 의존하면, 공급 판정은 입력한 사람의 주장을 되돌려 주는 것에 지나지 않습니다. 당사는 주택건설실적 통계(인허가·착공·분양·준공)를 별도로 수집하여 두 가지로 사용합니다.

**[표 5-6-1] 주택건설실적의 두 가지 역할**

| 역할 | 내용 |
|------|------|
| 선행 신호 | 인허가는 착공·분양의 선행 지표입니다. 전년 대비 30% 이상 급증하면, 현재 공급 부담이 낮더라도 중기 위험이 남아 있으므로 공급 판정을 '긍정'으로 닫지 않습니다 |
| 목록 교차검증 | 입력된 공급 목록(현장 인근)을 시군구 전체 인허가 실적과 대조합니다. 범위가 다르므로 인근 물량이 실적보다 작은 것은 정상이며, **뒤집혀 있을 때** — 인근 목록이 시군구 전체 인허가를 넘어설 때 — 중복 집계·취소 사업 포함 여부를 경고합니다 |

### 5.3.8 C7. 개발·도시계획 — 미래 변화의 검증

### 5.3.9 카테고리 간 교차 구조

일곱 카테고리는 병렬 나열이 아니라 검증의 그물망입니다. "이 현장의 실수요가 충분한가"라는 질문 하나에 대해 다섯 방향의 독립 측정이 수행됩니다.

**[표 5-7] 단일 질문에 대한 다중 검증 예시**

| 측정 방향 | 담당 카테고리 | 확인 내용 |
|-----------|--------------|-----------|
| 수요의 존재 | C1 인구·가구 | 가구 증가와 평형 구성의 정합성 |
| 지불 능력 | C2 고용·소득 | 소득 분포와 구매력의 뒷받침 |
| 물리적 도달 가능성 | C3 이동·교통 | 동선·접근성 위의 입지 여부 |
| 시장 표출 | C5 주택시장 | 청약·전세 수요의 실제 발현 |
| 경쟁 분산 | C6 공급 | 수요를 나눠 가질 경쟁 물량 |

다섯 측정이 수렴하면 강한 근거로 채택됩니다. 어긋나는 경우 — 예를 들어 가구는 증가하는데 청약이 미달인 경우 — **그 어긋남 자체가 원인 규명의 대상**이 됩니다. 어긋남을 덮지 않고 원인을 규명하는 것이 이 프레임워크와 시세 비교의 차이입니다.

## 5.4 방법론 엔진 — 여섯 가지 분석 기법

15개 레이어의 원천 데이터는 여섯 가지 방법론을 통과하며 결론으로 가공됩니다. **데이터 목록은 모방할 수 있으나 방법론의 규율은 모방하기 어렵다**는 점에서, 본 절이 제5장의 중심입니다.

### 5.4.1 GIS 공간분석 — 행정구역이 아닌 현장 중심 생활권

시·구 단위 통계를 현장 통계처럼 사용하는 것은 분양 분석의 가장 흔한 오류입니다.

당사는 현장 좌표를 확정한 후 직선거리권(500m·1km·3km), 도로 네트워크 거리권, 도보·차량·대중교통 시간권을 생성하고, 행정 경계 통계는 격자·집계구 중첩 가중으로 생활권에 재배분합니다.

**[표 5-8] 지표 성격별 공간단위 적용**

| 지표 | 우선 공간단위 | 적용 근거 |
|------|--------------|-----------|
| 상주인구·가구 | 격자·집계구·생활권 | 거주는 경계 기반 현상 |
| 고용·배후수요 | 차량·대중교통 시간권 | 통근은 시간 기반 현상 |
| 유동·상권 | 보행·도로 네트워크권 | 방문은 동선 기반 현상 |
| 학교·생활편의 | 도보·차량 시간권 (실제 출입구 기준) | 이용은 접근 기반 현상 |
| 비교단지 | 시장권 + 상품 유사성 | 비교는 대체 가능성 기반 |
| 개발계획 | 노선·구역·시설 영향권 | 영향은 사업 형상 기반 |

같은 "반경 1km"라도 하천·간선도로로 단절된 생활권과 연결된 생활권은 서로 다른 시장입니다. 공간 정밀성은 학술적 장식이 아니라, **"입지가 좋다"는 주장을 고객이 반박할 수 없는 형태로 만드는 실무 장치**입니다.

### 5.4.2 시계열 분석 — 스냅숏이 아닌 추세

현재 값 하나로는 방향을 알 수 없습니다. 인구·고용·거래·소비·공급의 다년 시계열로 다음을 구분합니다.

**[표 5-9] 시계열 분석의 네 가지 목적**

| 목적 | 내용 |
|------|------|
| 구조적 변화와 일시 효과의 분리 | 수년간 지속된 유입 추세와 단발 이벤트(대규모 입주, 일시 개발 특수)를 구분 |
| 선행·후행 관계 반영 | 전세가·거래량은 매매가에 선행하는 경향, 미분양은 공급 과잉에 후행하는 경향을 해석에 반영 |
| 이벤트 스터디 | 개발 사업의 발표·고시·착공·개통 전후를 처리지역과 비교지역으로 나눠 실제 가격 영향과 선반영 정도를 검증 |
| 미래 정보 누출 방지 | 과거 시점의 분석·검증에는 그 시점에 존재했던 정보만 사용. 백테스트(5.7)의 전제 조건 |

**최근 월은 아직 다 들어오지 않았습니다.** 부동산 거래신고는 계약일로부터 30일 이내에 하면 되고, 신고분이 공개 자료에 반영되기까지 며칠이 더 걸립니다. 따라서 **수집 시점의 최근 1~2개월 거래는 항상 과소집계 상태**입니다. 이를 무시하면 두 가지가 조용히 어긋납니다. 첫째, 월별 집계의 마지막 점은 표본이 얇아 흔들리는데 추세 회귀에서 끝점의 영향력이 가장 크므로, 미완결 월 하나가 추세의 방향을 바꿀 수 있습니다. 둘째, 거래 회전율은 분자(거래건수)만 덜 차고 분모(기간)는 그대로여서 체계적으로 낮게 산출되며, 임계값 근처에서 '환금성 취약' 오판정을 만듭니다.

리포트는 법정 신고기한이라는 **결정적 규칙**으로 월별 완결 여부를 판정하고, 미완결 월을 추세·회전율 산출에서 제외한 뒤 **제외한 월과 건수를 리포트 3-2절에 그대로 표기**합니다. 거래량이 적다는 관찰만으로 월을 빼지는 않습니다 — 그렇게 하면 실제 시장 냉각을 데이터 결함으로 오인해 하락 신호를 지워 버리기 때문입니다. 거래량 급감은 무작위 변동 범위(포아송)를 넘을 때에 한해 별도 표시로만 남깁니다.

같은 규율이 백테스트에도 적용됩니다. 과거 시점을 재현할 때 "그때 있었던 정보"라며 쓰는 데이터에는 실제로는 아직 신고되지 않았을 거래가 섞여 있습니다 — 지금 돌아보면 다 들어와 있기 때문입니다. 이를 그대로 두면 검증 성적이 실시간 운영보다 좋게 나오므로, 백테스트도 동일한 지연을 적용해 잘라 냅니다. **검증이 운영보다 유리한 조건에서 이뤄지면 검증의 의미가 없습니다.**

### 5.4.3 교차검증 — 세 방향의 대조

**[표 5-10] 교차검증의 세 층위**

| 층위 | 방법 | 검증 예시 |
|------|------|-----------|
| 지표 간 교차 | 같은 현상을 다른 지표로 확인 | 가격 상승 주장을 거래량·취소거래율과 대조하여 "거래 없는 호가 상승"을 배제 |
| 레이어 간 교차 | 한 레이어의 결론을 독립 레이어로 확인 | "직주근접 수요"(L4)를 실제 통근 O/D(L7)와 청약 신청 지역 분포(L12)로 검증 |
| 유사지역 비교 | 조건이 유사한 지역과 대조 | 교통·세대수·준공연차·공급환경이 유사한 지역과 비교하여 현장 고유 효과와 시장 전반 효과를 분리 |

비교단지·비교지역의 선정 기준은 재현 가능하도록 문서화되며, 포함·제외 사유가 근거원장(5.9)에 기록됩니다.

### 5.4.4 반대근거 분석 — 반증을 먼저 탐색한다

모든 핵심 결론에 대해 **"이 결론을 무너뜨릴 수 있는 데이터는 무엇인가"**를 명시적으로 탐색합니다.

**[표 5-11] 반대근거 탐색 항목**

| 결론 유형 | 탐색하는 반대근거 |
|-----------|-------------------|
| 상승 사례 | 같은 조건에서 가격이 움직이지 않은 반대사례와 그 원인 |
| 개발호재 | 소음·혼잡·추가 공급·지연·민원·환경 위험 등 부정효과 |
| 수요 논리 | 이 수요가 경쟁 현장으로 이동할 조건 |
| 공급 희소성 | 미반영된 잠재 공급(정비사업, 가용지, 인접 시장권) |

탐색된 반대근거는 폐기되지 않고 근거카드의 "반대" 항목에 기록되어(5.9), **상담 단계의 거절 대응 논리(제6장)로 재사용**됩니다. 고객이 제기할 반론을 분석 단계에서 먼저 통과시키는 구조입니다.

### 5.4.5 신뢰도 평가 — 모든 판단에 확신 수준을 표시한다

**데이터 수준.** 모든 레이어·지표는 다섯 축으로 평가되어 A~D 등급을 받습니다(상세는 부록 A).

**[표 5-12] 데이터 적합성 평가 5축**

| 평가축 | 배점 | 확인 내용 |
|--------|------|-----------|
| 공간 적합성 | 25 | 현장·생활권·격자·시간권 수준으로 집계 가능한가 |
| 시간 적합성 | 25 | 분석 기준일과 시계열 빈도·지연이 적합한가 |
| 정의·품질 | 20 | 측정 대상·표본·정제·결측·통계 개편이 명확한가 |
| 재현성·추적성 | 15 | 원문·버전·추출·계산을 다시 확인할 수 있는가 |
| 권한·지속성 | 15 | 수집·가공·저장·공개·재배포가 허용되고 지속 가능한가 |

C등급 데이터는 탐색·가설 생성용으로만 사용하며, D등급은 분석·광고 사용을 금지합니다.

**판단 수준.** 카테고리별 결론에는 네 가지 속성이 함께 표시됩니다.

**[표 5-13] 판단의 4속성**

| 속성 | 내용 |
|------|------|
| 방향 | 현장가치에 긍정적인가, 부정적인가, 중립인가 |
| 강도 | 효과의 크기는 어느 정도로 추정되는가 |
| 신뢰도 | 근거 데이터의 등급과 레이어 간 수렴 정도는 어떠한가 |
| 변화 | 직전 분석 대비 판단이 바뀌었는가, 바뀌었다면 무엇 때문인가 |

신뢰도가 기준에 미달하면 수치 제시를 포기하고 정성 등급으로 전환하거나 판단을 유보합니다. **낮은 확신을 높은 확신처럼 표현하지 않는 것**이 본 방법론의 최종 규율입니다.

**모르는 것은 0이 아닙니다.** 표본이 기준에 미달하면 해당 지표를 '미산출'로 표기하며, 0이나 공란으로 대체하지 않습니다. 예를 들어 소득 표본이 부족해 구매 가능 가구 비율을 낼 수 없을 때 "0%"로 적으면 "수요가 전혀 없다"는 전혀 다른 주장이 되고, 그 값이 수요 판정의 점수로 들어가면 판정 자체가 오염됩니다. 미산출 지표는 판정 계산에서 제외되고 그 사유가 함께 기록됩니다.

### 5.4.6 조정계수의 교정 — 계수도 검증 대상이다

품질조정 가격 밴드(5.5)는 비교 거래를 연식·층·거래시점 차이만큼 보정해 표준화합니다. 그 보정률이 문헌·경험 기반의 초기값에 머물면, **밴드 전체가 검증되지 않은 계수 위에 서 있는 셈**입니다. 다른 모든 수치를 검증하면서 계수만 예외로 두는 것은 일관성이 없습니다.

당사는 계수를 실거래로 추정하고, 추정치가 검증을 통과할 때만 교체합니다.

**[표 5-13-1] 조정계수 교정 절차**

| 단계 | 내용 |
|------|------|
| ① 추정 | ㎡당 가격의 로그값을 연식·층 구간·면적·거리·브랜드·분양권 여부·시간에 회귀합니다. 연식과 시간 추세를 동시에 넣어 '구축 할인'과 '시장 등락'을 분리합니다 |
| ② 게이트 | 계수마다 표본 수·통계적 유의성·부호·크기 상한을 검사합니다. 하나라도 통과하지 못하면 그 계수는 **기존 값을 유지**하고 사유를 기록합니다 |
| ③ 홀드아웃 검증 | 앞 70% 기간으로만 계수를 재추정해 뒤 30% 기간에 적용하고, 조정 후 잔차 분산이 실제로 줄어드는지 확인합니다. 줄지 않으면 기각합니다 |
| ④ 표기 | 교체 여부와 무관하게, 리포트의 모델 카드에 현재 계수의 출처가 '초기값(미교정)'인지 '실데이터 교정값'인지 명시됩니다 |

**적중률을 채택 기준으로 쓰지 않는 이유.** 적중률(부록 E.2)은 구간의 '폭'이 제대로 보정됐는지를 재는 지표입니다. 계수를 바꾸면 밴드와 실현값이 같은 방향으로 함께 움직이므로 적중률은 거의 변하지 않습니다 — 계수 정확도에 둔감한 지표입니다. 따라서 채택은 잔차 분산으로 판단하고, 적중률은 크게 나빠지지 않았는지 확인하는 안전장치로만 사용합니다.

계수는 자동으로 좋아지지 않습니다. **교정이 기각되면 기존 예시값이 유지되고, 그 사실이 리포트에 남습니다.** 이 절차의 목적은 계수를 바꾸는 것이 아니라, 계수가 어떤 상태인지 발주처가 알 수 있게 하는 것입니다.

## 5.5 가격·시장 검증 모듈

프레임워크의 15개 레이어가 수요·공급·흐름을 검증한 위에서, 가격 질문에 답하는 전용 모듈이 작동합니다.

**[표 5-14] 가격 검증 4요소**

| 요소 | 산출 내용 | 활용 |
|------|-----------|------|
| 총취득원가 | 분양가 + 옵션 + 발코니 확장 + 취득 부대비용(구간 누진 세율) | 고객이 실제로 계산하는 금액. **비교 거래도 같은 규칙으로 환산**해야 비교가 성립함 |
| 품질조정 현재가격 | 비교단지와의 연식·입지·규모·브랜드·평형·층·거래시점 차이를 조정 | "같은 가격"이 아니라 **"같은 조건"**으로 비교 |
| 시장 대비 위치 | 시장 지수 대비 해당 생활권·단지의 초과·미달 성과 | 현장 가격이 시장 흐름 안에서 어느 구간에 있는지 판정 |
| 환금성 | 거래량·회전율·매도 소요기간·전세 유동성·가격 분산 | 투자 수요의 핵심 질문에 대한 답. 유리하지 않은 결과도 기록 |

**비교의 양쪽에 같은 기준을 적용합니다.** 총취득원가로 비교한다는 원칙은 현장에만 적용하면 오히려 왜곡을 만듭니다. 비교단지를 사는 사람도 취득 부대비용을 부담하는데, 현장에만 세금을 얹고 비교 거래는 신고가 그대로 쓰면 현장이 부대비용만큼 비싸 보이고 판정 ①이 '밴드 상단(가격 저항 위험)' 쪽으로 계통적으로 기웁니다. 당사 시스템은 **현장과 비교 거래 모두를 같은 함수로** 총취득원가로 환산합니다.

세율도 정액이 아닙니다. 주택 유상거래 취득세는 가액 구간별 누진이므로(6억 이하 1%, 6~9억 누진, 9억 초과 3%), 6억 이하 주택에 3.3%를 일괄 적용하면 2%p 넘게 과대계상됩니다. 여기에 지방교육세(취득세율의 10%)와 전용 85㎡ 초과 시 농어촌특별세(0.2%)를 반영하며, **타입별로 실제 적용된 부대비용률을 리포트에 표기**합니다. 전제(1주택 유상거래, 중과·감면 미적용, 중개보수·법무비용 미포함)는 LIMITATION으로 병기되고, 그 전제가 판정을 좌우하는지는 강건성 검사(5.8.1)에서 다주택 중과 시나리오로 확인합니다.

**산출 정밀도.** 가격 검증은 현장 총평 수준에서 끝나지 않습니다. 품질조정 모델은 평형(타입)·층·향·동 위치의 차이를 조정 변수로 반영하므로, 산출물은 **타입·층 구간 단위의 가격 밴드**로 제시됩니다. 이 정밀도는 두 가지 실무 요구에 대응합니다 — 첫째, 잔여 세대의 타입·층별 판촉 우선순위 판단. 둘째, 상담 현장에서 "이 동·이 층은 왜 이 가격인가"라는 세대 단위 질문에 대한 근거 있는 답변.

**전세 기반 하방 점검.** 매매 실거래만으로는 "이 가격이 비싼가"에는 답할 수 있어도 **"얼마나 밀릴 수 있는가"**에는 답할 수 없습니다. 매매가에는 미래 기대가 섞여 있기 때문입니다. 전세가는 실거주 수요가 지금 지불하는 금액이라 기대가 섞이지 않으므로, 전세가율을 가격 하락 시의 **완충 두께**로 읽습니다.

**[표 5-14-1] 전세 기반 하방 점검**

| 산출 | 내용 |
|------|------|
| 전세가율 | 전세 ㎡단가 ÷ 매매 ㎡단가. 70% 이상 하방 지지 두터움 / 55% 미만 완충 얇음 |
| 전세가율 추세 | 직전 동일 기간 대비 증감. 상승은 실거주 수요 강화, 하락은 약화 신호 |
| 전월세전환율 | 월세 시장이 요구하는 수익률. 전세 대비 월세 부담의 상대 수준 |
| 분양가 전세 충당율 | 총취득원가 중 전세보증금으로 회수 가능한 비율. 투자 수요의 실제 자금 부담을 근거 있는 수치로 설명 |

가격 판정(5.8 ①)에는 다음과 같이 반영됩니다 — 총취득원가가 밴드 상단인데 전세 완충까지 얇으면 두 신호가 같은 방향을 가리키므로 하방 위험의 **강도를 상향**하고, 완충이 두터우면 **강도를 하향**합니다.

*분석 규칙 두 가지.* 첫째, **갱신 계약은 제외**합니다 — 갱신요구권·상한제의 영향으로 신규 체결가와 가격 형성 논리가 다르기 때문이며, 제외 건수는 리포트에 표기됩니다. 둘째, 전세 표본이 최소 기준에 미달하면 전세가율을 산출하지 않고 그 사실을 기재합니다.

**청약 수요 전망 (예상 청약경쟁률).** 청약 방식으로 공급되는 현장에 대해서는 예상 청약경쟁률을 **구간(범위)과 미달 위험**으로 제시합니다.

**[표 5-14-2] 청약 수요 전망 모듈**

| 구성 | 내용 |
|------|------|
| 입력 변수 | 분양가와 주변 시세의 격차(품질조정 기준), 시장권 청약 이력(경쟁률·미달·가점 커트라인), 공급 파이프라인과 동시 분양 물량, 수요 기반(C1·C2), 미분양 재고, 청약 제도·전매 조건 |
| 산출 | 전체 및 타입별 예상 경쟁률 구간, 순위 내 마감·미달 위험 등급, 결과를 좌우하는 상위 민감 변수 |
| 검증 | 과거 시장권 청약 실적 대비 백테스트. 예측 구간의 실적 적중률을 산출하여 리포트에 병기 |
| 표현 통제 | 전망은 FORECAST 등급(5.9.1)으로 분류. 조건·범위 없이 단일 수치로 광고에 사용 금지 |

청약 전망의 실무 가치는 숫자 자체가 아니라 **의사결정 시점의 이동**에 있습니다. 미달 위험이 사전에 식별되면 분양가·타입 구성·판촉 조건의 조정을 청약 전에 검토할 수 있고, 높은 경쟁이 전망되면 청약 후 미계약분 관리와 정당계약 전환 준비에 자원을 배분할 수 있습니다. 모듈의 기술 명세와 검증 절차는 부록 E에 정의합니다.

**실부담 시뮬레이션.** 총취득원가는 구매 시점의 비용입니다. 고객의 실제 질문은 한 단계 더 나아갑니다 — "자기자본이 얼마 필요하고, 매월 얼마를 부담하게 되는가." 이 질문에 답하기 위해 총취득원가 모듈을 실부담 시뮬레이션으로 확장합니다.

**[표 5-14-3] 실부담 시뮬레이션 구성**

| 산출 | 내용 |
|------|------|

**분양가 결정 시뮬레이션.** 위 모듈들은 "지금 가격이 어디쯤인가"에 답합니다. 그러나 시행사가 실제로 결정해야 하는 것은 **"분양가를 얼마로 잡을 것인가"**입니다. 진단과 결정 사이의 이 간극을 메우기 위해, 후보 가격대를 훑으며 각 가격에서 무엇이 달라지는지를 같은 근거로 계산합니다.

|----|------------------------------|
| 가격 위치 | 품질조정 비교 밴드 대비 하단 / 내 / 상단 |
| 수요 | 실부담 기준 구매 가능 가구 비율 |
| 청약 | 예상 경쟁률 구간 — 가격이 바뀌면 시세 갭이 바뀌고, 그러면 유사 사례 매칭 자체가 바뀝니다. 그 연쇄를 그대로 반영합니다 |
| 위험 | 순위 내 미달 위험 |
| 수입 | 총 분양수입 — 의사결정의 반대편 축 |

**권고는 예언이 아니라 규칙입니다.** 두 조건 — ① 미달 위험이 임계 이하 ② 총취득원가가 비교 밴드 상단을 넘지 않음 — 을 동시에 만족하는 후보 중 **가장 높은 가격**을 권고하며, **그 판단 기준을 문장으로 함께 제시**합니다. 조건을 바꾸면 답도 바뀐다는 사실이 발주처에게 보여야 하기 때문입니다.

권고하지 않는 경우도 사유를 구분해 말합니다. 비교 밴드 표본이 부족해 가격 위치를 판단할 수 없는 경우, 유사 청약 사례가 부족해 미달 위험을 산출할 수 없는 경우, 산출은 됐으나 두 조건을 만족하는 후보가 없는 경우 — 세 경우의 대응이 서로 다르므로 뭉뚱그리지 않습니다. 특히 세 번째는 마케팅이 아니라 **원가·상품 구성의 재검토를 발주처 안건으로 제기해야 하는 신호**입니다(5.8 판정 조합 참조).

**세분화와 표본의 균형 (롤업 규칙).** 타입·층 구간으로 세분화할수록 비교 표본은 감소합니다. 당사는 구간별 최소 표본 기준을 정의하고, 기준 미달 시 해당 구간의 수치를 상위 집계(타입 구간 → 타입 전체 → 현장)로 자동 롤업하며, **롤업 사실을 리포트에 명시**합니다. 표본이 지지하지 않는 세분화 수치를 제시하지 않는 것 — 이것이 세대 단위 정밀도 주장과 검증 가능성을 양립시키는 방법입니다.

가격 결론은 C1~C7의 검증 결과와 정합할 때만 채택됩니다. **수요·공급·소득이 지지하지 않는 가격 우위 판정은, 시세 비교가 어떤 숫자를 보여주든 채택하지 않습니다.**

## 5.6 개발호재 검증 — 성숙도 엔진

교통·도시계획·공공투자는 고객 관심이 가장 높은 동시에 과장 위험이 가장 큰 영역입니다. 당사는 두 가지를 분리하여 검증합니다.

### 5.6.1 실현 가능성 — 성숙도 단계 판정

철도·도로·도시계획을 동일한 "예정"으로 묶지 않고, 단계별로 구분하여 각 단계의 공식 원문(고시문, 예산서, 입찰·계약, 보상, 공정 자료)을 근거로 저장합니다.

**[표 5-15] 성숙도 단계와 표현 통제**

| 단계군 | 해당 상태 | 광고·상담에서의 취급 |
|--------|-----------|---------------------|
| 검토 단계 | 아이디어·민원·공약·검토 요청 | 가능성으로만 표시. 확정적 표현 금지 |
| 추진 단계 | 계획 반영·타당성 조사·설계·인가 | 일정과 변경 위험을 병기 |
| 확정·실행 단계 | 예산 집행·계약·보상·착공·개통 | 현장 영향과 가격 반영 여부를 검증하여 표시 |

### 5.6.2 현장 관련성 — 계산에 의한 검증

**[표 5-16] 현장 관련성 검증 항목**

| 검증 항목 | 내용 |
|-----------|------|
| 공간 관련성 | 노선·역·IC·구역과 현장 간 거리, 개통 전후 이동시간 변화(L8 시뮬레이션), 도달 가능 인구·일자리 변화 |
| 시장 선반영 | 발표 이후 인근 가격에 기대효과가 이미 반영됐는가 (5.4.2 이벤트 스터디) |
| 부정효과 | 소음·혼잡·추가 공급·공사 지연·민원·환경 위험 |
| 중복 방지 | 동일 프로젝트의 계획·예산·착공을 별도 호재로 중복 합산하지 않음 |

호재의 기대효과는 **"실현 가능성 × 현장 관련성 × 조건부 영향"**의 구조로 설명하되, 수치의 정밀도보다 구성 요소와 불확실성의 분리를 우선합니다.

## 5.7 조건부 시나리오와 백테스트

미래 가격은 단일 숫자로 제시하지 않습니다.

**[표 5-17] 시나리오 구성**

| 구성 요소 | 내용 |
|-----------|------|
| 시나리오 범위 | 하방(보수)·기준·상방(상승)의 세 구간 |
| 전제 변수 | 공급·금리·소득·접근성·사업 진척 |
| 병기 항목 | 각 시나리오의 전제 조건, 근거, 하락 위험, 추가 확인사항 |
| 민감도 | 어느 변수가 변동할 때 결론이 얼마나 바뀌는가 |

민감도를 함께 제시함으로써 시나리오가 "세 개의 숫자"가 아니라 **판단의 지도**로 기능하게 합니다.

모델의 신뢰성은 백테스트로 관리합니다. 과거 시점에서 사용 가능했던 정보만으로 예측하고 실제 결과와 비교하는 시계열 검증(5.4.2)을 원칙으로 하며, 표본 부족이나 시장 구조 변화가 큰 경우 모델 수치를 축소하거나 정성 등급으로 전환합니다(5.4.5). 구간 예측의 적중률 관리 기준과 예측 이력의 봉인·대조 절차는 부록 E에 정의합니다.

**검증은 운영과 같은 코드로 수행됩니다.** 백테스트가 별도 스크립트로 돌면 "리포트에 나가는 구간"과 "검증되는 구간"이 달라질 수 있습니다. 당사는 두 경로가 동일한 산출 함수를 호출하도록 구성하여, 검증된 것이 곧 납품되는 것임을 구조적으로 보장합니다. 조정계수 역시 이 백테스트와 홀드아웃 검증(5.4.6)을 통과할 때만 교체됩니다.

## 5.8 종합 판정 — 하나의 점수로 합산하지 않는다

서로 다른 의미를 가진 결과를 하나의 "AI 점수"로 합산하는 방식은 채택하지 않습니다. 합산 점수는 판단을 단순화하지만, 무엇이 강점이고 무엇이 위험인지를 가려 의사결정을 저해합니다.

**[표 5-18] 네 개의 독립 판정**

| 판정 결과 | 답하는 질문 | 주요 근거 |
|-----------|------------|-----------|
| ① 현재 가격 위치 | 총취득원가가 품질과 시장을 고려할 때 어느 구간인가? | C5 + 가격 모듈(5.5) |
| ② 수요 지속성 | 실거주·근무·이동·구매 수요가 입주 시점까지 유지될 조건은 무엇인가? | C1·C2·C3 |
| ③ 공급·환금성 위험 | 경쟁 입주·미분양·거래 부족이 가격과 판매에 어떤 부담을 주는가? | C5·C6 |
| ④ 촉매·실행 가능성 | 외부 계획과 현장 개선 과제 중 실현 가능하고 영향력 있는 것은 무엇인가? | C7 + 성숙도 엔진(5.6) |

각 판정에는 5.4.5의 4속성(방향·강도·신뢰도·변화)이 표시됩니다. 판정 ①의 산출물에는 **타입별 적정 가격 밴드**와 **전세 기반 하방 점검**이, 판정 ②의 산출물에는 **예상 청약경쟁률 구간과 미달 위험 등급**(5.5)이 포함됩니다 — 모두 단일 수치가 아니라 5.7의 조건부 범위 규율을 적용한 구간 제시입니다. 네 판정을 종합한 결과는 **분양가 결정 시뮬레이션**(5.5)으로 이어져, 진단이 가격 결정 안건으로 전환됩니다.

각 판정의 근거에는 어떤 레이어가 기여했는지가 함께 표기됩니다. 예를 들어 판정 ②에는 지역 통계(L1·L2·L4)·인구이동(L3)·생활이동(L7)·교통 접근성(L8)·생활 인프라(L9)·실부담·청약 전망이 각각 별도 항목으로 나열되므로, 발주처는 **어느 근거가 판정을 이끌었고 어느 근거가 미산출이었는지**를 직접 확인할 수 있습니다.

**[표 5-19] 판정 조합에 따른 판매 전략 방향 (예시)**

| 판정 조합 | 우선 전략 |
|-----------|-----------|
| ① 가격 위치 불리 + ② 수요 지속성 유리 | 가격 조정보다 총취득원가 비교 논리와 수요 타깃 정밀화 |
| ② 수요 지속성 약함 + ③ 공급 위험 높음 | 마케팅 강화보다 조건 재검토를 발주처 안건으로 제기 |
| ④ 촉매 성숙도 낮음 | 호재 의존 메시지를 배제하고 현재 가치 중심으로 설득 구성 |

**분석이 판매 전략의 형태를 결정합니다.** 이것이 "광고 전에 팔릴 근거를 검증한다"(제1장)의 구체적 의미입니다.

### 5.8.1 판정 강건성 검사 — 이 결론은 가정이 바뀌면 뒤집히는가

판정은 데이터만으로 나오지 않습니다. 연식 조정계수, LTV·DSR 한도, 단계별 공급 실현률, 촉매 실현 가능성처럼 **선택된 가정**이 함께 들어갑니다. 이 가정들은 리포트에 LIMITATION으로 기재되지만, 기재되어 있다는 것과 그 가정이 결론을 좌우한다는 것을 발주처가 아는 것은 다릅니다.

그래서 리포트는 매 회차 각 가정을 합리적 범위에서 흔든 뒤 **운영과 동일한 판정 함수로** 판정을 다시 계산합니다. 방향이 유지되면 데이터가 지지하는 결론이고, 뒤집히면 그 판정은 가정에 의존합니다. 검사 결과는 리포트 1-2절에 표로 실리며, 뒤집힌 판정은 결론 요약 바로 아래에도 표기됩니다.

**[표 5-19-1] 판정별 강건성 검사 항목**

| 판정 | 흔드는 가정 | 교란 폭 |
|------|-------------|---------|
| ① 현재 가격 위치 | 연식 조정계수 | ×0.5 / ×1.5 (조정 상한도 같은 규칙으로 재계산) |
| ① 현재 가격 위치 | 시점수정률 | ±2%p/년 |
| ② 수요 지속성 | LTV·DSR 한도 | LTV 0.5→0.4 · DSR 0.4→0.3 (규제 강화) |
| ② 수요 지속성 | 가용 자기자본 배수 | 연소득×4 → ×3 |
| ③ 공급·환금성 위험 | 단계별 공급 실현률 | 전 단계 ±20%p |
| ③ 공급·환금성 위험 | 환금성 '양호' 기준 | 연 회전율 6% → 9% |
| ④ 촉매·실행 가능성 | 단계별 실현 가능성 | ±10%p |

검사에는 세 가지 규율이 적용됩니다. 첫째, **판정 로직을 복제하지 않습니다** — 교란은 운영 함수의 파라미터로만 들어가며, 검사 대상과 검사 도구가 갈라지면 검사 자체가 무의미해지기 때문입니다. 둘째, **흔들 수 없는 가정은 '검사 안 함'으로 남깁니다** — 소득 표본이 없어 수요 판정을 재계산할 수 없으면 그 사실을 사유와 함께 적습니다. 셋째, **교란 폭 자체가 가정임을 밝힙니다** — 폭은 상수로 노출되어 있고 근거원장에 한계로 등재됩니다.

결과는 상담 단계까지 이어집니다. 가정 의존으로 판정된 축의 답변은 판매 논리 산출물(제6장)에서 **단정형 문장 사용이 차단**되고 "현재 가정 기준"이 병기됩니다. 분석이 스스로 흔들린다고 밝힌 결론을 상담 조직이 확언으로 사용하는 것을 구조적으로 막기 위해서입니다.

## 5.9 신뢰 통제 장치

분석 결과가 광고·상담으로 전달되는 경로에는 세 겹의 통제가 있습니다.

### 5.9.1 다섯 가지 표현 등급

분석의 모든 문장은 다음 중 하나로 분류되며, 등급에 따라 사용 가능한 표현의 강도가 달라집니다.

**[표 5-20] 분석 표현의 5등급**

| 표시 | 의미 | 사용 예시 |
|------|------|-----------|
| FACT | 공식 자료에서 직접 확인한 사실 | 기준일 현재 실거래, 고시, 예산, 착공 상태 |
| CALCULATION | 공개된 입력값과 산식으로 산출한 계산 | 총취득원가, 시간권 인구, 공급 부담 |
| INFERENCE | 여러 근거를 연결한 해석 | 직주근접 수요 가능성, 가격 저항의 원인 |
| FORECAST | 조건에 따라 달라지는 미래 시나리오 | 가정별 가격 범위 |
| LIMITATION | 데이터·권한·방법론의 한계 | 민간 데이터 미확보, 주소 매칭 오차, 표본 부족 |

LIMITATION을 등급의 하나로 명시하는 이유는, **분석이 말할 수 없는 것을 말할 수 없다고 기록하는 것**이 말할 수 있는 것의 신뢰를 지키는 방법이기 때문입니다.

### 5.9.2 근거원장 — 모든 주장에 검증 가능한 주소를 부여한다

모든 핵심 주장은 근거카드로 관리되어 역추적 가능합니다.

**[표 5-21] 근거카드 구성**

| 항목 | 기록 내용 |
|------|-----------|
| 결론 | 무엇을 판단했는가 |
| 근거 | 기관·데이터명·문서번호·기준일 |
| 산출 | 분석 범위·단위·계산 방식 |
| 반대 | 결론을 약화하는 데이터 |
| 영업 | 사용 가능 문장·금지 문장·추가 확인사항 |

개발호재에는 별도의 **촉매카드**를 고객용으로 제공합니다 — 프로젝트 공식명·사업주체, 현장과의 거리·시간 관계, 공식 추진 단계와 기준일, 정부 원문 링크, 예산 집행 현황, 당사 계산, 반대근거, 사용 가능·조건부·금지 문장.

내부적으로는 데이터·계산·주장·프로젝트 상태·광고사용의 5개 원장이 이를 뒷받침합니다. 특히 **광고사용 원장**은 "이 문구를 언제, 누가, 어떤 근거로 승인했고, 어떤 조건에서 철회되는가"를 기록하여 표현 책임의 소재를 명확히 합니다.

**리포트에 실리는 형태.** 근거원장은 내부 관리 문서에 그치지 않고, **진단리포트의 한 절로 함께 납품**됩니다. 리포트를 읽는 사람이 어떤 수치든 짚어서 되물을 수 있어야 하기 때문입니다.

**[표 5-21-1] 근거원장 등재 항목**

| 항목 | 기록 내용 |
|------|-----------|
| ID | 본문에서 참조하는 식별자 (E-01, E-02 …) |
| 지표·값 | 무엇이 얼마인가 |
| 산출 | 어느 모듈의 어떤 규칙으로 계산했는가 — 정제 룰 버전, 모델 버전, 계수 출처 포함 |
| 데이터 | 어떤 수집 이력에 기반하는가 — 출처명·수집 시각·응답 해시(SHA-256) |
| 표본 | 몇 건에서 나왔는가 |
| 등급 | FACT / CALCULATION / INFERENCE / FORECAST / LIMITATION (5.9.1) |
| 한계 | 이 수치를 읽을 때 반드시 함께 봐야 하는 제약 |

**산출하지 못한 지표도 '미산출'로 등재합니다.** 없는 근거를 조용히 빼면, 독자는 그 지표가 *검토되지 않았는지* 아니면 *검토했으나 표본이 기준에 미달했는지* 구분할 수 없습니다. 그 구분이 신뢰의 핵심이므로 빼지 않고 사유와 함께 남깁니다.

인증키·원본 요청 URL은 원장에 기록되지 않습니다. 출처명과 응답 해시만으로 재현·대조가 가능하며, 자격증명이 산출물로 새어 나가지 않도록 통제합니다.

### 5.9.3 역할 분리 — 본 문서에서 AI의 역할을 정의하는 유일한 절

AI가 담당하는 것은 **실행의 가속**입니다. 수백 개 지표의 수집·정규화, 문서 검색과 구조화, 이상 신호 탐색, 초안 생성이 그 범위입니다. 방법론 적용의 타당성, 결과의 해석, 표현의 근거 적합성은 사람이 판단합니다.

**[그림 5-2] 분석 처리 6단계와 책임 주체**

```
① 수집          ② 정규화         ③ 분석           ④ 교차검증
공식·허가 데이터 → 기준일·공간·단위 → 방법론 엔진 적용 → 반대지표·원문 대조
     [AI]            [AI]           [AI + 분석가]      [AI + 분석가]
                                                            │
                                                            ▼
                              ⑥ 현장 승인        ⑤ 사람 검수
                              판매 주장 확정   ←  산식·표현·근거 검증
                                [시행사]            [분석가]
```

**[표 5-22] 주체별 담당 범위**

| 주체 | 담당 | 담당하지 않는 것 |
|------|------|------------------|
| AI | 데이터 구조화·비교·이상신호 탐색, 문서 검색, 초안 생성 | 최종 판단, 표현 승인 |
| 분석가 | 방법론 적용의 타당성, 공식 원문·산식·비교대상·표현 검수 | 분양조건 결정 |
| 시행사 | 분양조건 제공, 광고 표현 최종 승인 | — |

> **책임 원칙.** AI가 생성한 문장과 수치는 자동으로 광고에 게시되지 않습니다. 분석가와 승인권자가 근거·표현·개인정보를 검토한 뒤 사용합니다.

분석의 품질은 알고리즘이 아니라 방법론의 규율에서 나옵니다.

## 5.10 데이터 커버리지의 사전 공개와 분석 중단 조건

### 5.10.1 커버리지표의 사전 제출

모든 현장에서 15개 레이어 전부를 같은 수준으로 분석할 수 있는 것은 아닙니다. 당사는 이 한계를 계약 후에 드러내지 않고 **계약 전에 커버리지표로 먼저 제출합니다.**

레이어·지표별로 "확보 가능 · 조건부 · 미확보 · 대체 가능"을 판정하며(세부 기준은 부록 A), 미확보 항목은 분석 범위를 재설계하거나 해당 판매 주장을 제외합니다. 민간 데이터(모바일 유동인구, 익명 카드소비, 민간 매물)는 제휴·라이선스·비용 확인이 선행되는 별도 협의 대상임을 처음부터 명시합니다.

**커버리지표는 손으로 작성하지 않습니다.** 실제 수집 상태로부터 자동 생성되어, 어떤 레이어가 어떤 사유로 어떤 판정을 받았는지가 실행 결과와 항상 일치합니다. 제안 단계에서 유리하게 적어 두고 운영 단계에서 달라지는 일이 구조적으로 발생하지 않습니다. 현재 구현 기준으로 15개 레이어 중 **13개가 연동**되어 있으며, 미연동 2개(L6 유동인구·L10 카드소비)는 민간 라이선스 협의 대상입니다(상세는 부록 F).

### 5.10.2 분석 중단 조건

다음의 치명적 결함이 확인되면 해당 분석을 수치로 제시하지 않고, 분석 중단·대체 자료·제한 판정 중 하나를 명시적으로 선택합니다.

**[표 5-23] 치명적 결함 목록**

| 결함 유형 | 내용 |
|-----------|------|
| 대상 미확정 | 현장 위치·경계·사업 대상이 확정되지 않은 상태 |
| 시점 오류 | 기준일 부재, 또는 분석 시점 이후 정보가 과거 예측에 혼입된 상태 |
| 공간 오용 | 시·구 통계를 생활권 값으로 대체하면서 오차를 표시하지 않은 상태 |
| 재현 불가 | 원문·출처·계산을 재현할 수 없거나 라이선스·재배포 권한이 없는 상태 |
| 표본 결함 | 표본 과소, 결측·중복·좌표 오류가 결과의 방향을 바꾸는 상태 |
| 중복 집계 | 동일 개발 프로젝트를 중복 집계했거나 검토 단계를 확정처럼 취급한 상태 |
| 개인정보 결함 | 고객 개인정보가 적법한 동의·위탁·보관 기준 없이 결합된 상태 |

"분석 불가"를 판정하는 능력은 분석 역량의 일부입니다. 모든 현장에서 모든 항목을 분석할 수 있다고 제시하는 제안은, 그 신뢰성을 별도로 검토할 필요가 있습니다.

**[표 5-23-1] 중단·미산출의 세 단계 구분**

이 규율은 선언이 아니라 실행 시점에 강제됩니다. 결함의 성격에 따라 대응이 달라집니다.

| 단계 | 발생 조건 (예시) | 처리 |
|------|------------------|------|
| 분석 중단 | 현장 좌표 미확정, 타입별 세대수 합 불일치, 분양가 단위 오류, 기준일 이후 거래·계약 혼입, 정제 후 비교 거래 0건 | 리포트를 생성하지 않고 사유와 조치 방향을 반환 |
| 지표 미산출 | 해당 지표의 표본이 최소 기준 미달 (전세가율, 구매 가능 가구 비율, 청약 전망 등) | 리포트는 생성하되 해당 수치를 내지 않고, 판정 계산에서도 제외한 뒤 사유를 근거원장에 등재 |
| 정밀도 하향 | 타입·층 구간 표본이 최소 기준 미달 | 상위 집계로 롤업하고 롤업 사실을 표기 (5.5) |

기준일 이후 정보의 혼입은 매매·전월세 양쪽에 동일하게 적용됩니다. 전세가율이 가격 판정에 직접 들어가는 이상, 전월세 계약에도 매매와 같은 규율이 적용되어야 하기 때문입니다.

## 5.11 가치상승 실행과제와 살아 있는 리포트

### 5.11.1 현장이 통제 가능한 개선 과제

외부 호재를 기다리는 것만으로는 현장가치를 통제할 수 없습니다. 분석 이후, 시행사와 현장이 직접 개선할 수 있는 과제를 통제 가능성 기준으로 분류하여 제안합니다.

**[표 5-24] 가치상승 실행과제 분류**

| 분류 | 과제 예시 | 현장 통제력 |
|------|-----------|------------|
| 즉시 개선 | 분양가 구조, 옵션 구성, 상품 설명, 정보 공개 방식 | 높음 |
| 상품 개선 | 주차·커뮤니티·조경·에너지·평면 | 높음 |
| 접근성 개선 | 셔틀, 버스정류장, 보행 연결, 진출입 동선 | 중간 |
| 생활편의 유치 | 어린이집·의료·상업·문화시설 | 중간 |
| 공공협의 | 도로·학교·공원·교통 개선 | 중저 |
| 장기 계획 | 철도·광역도로·도시계획 변경 | 낮음 |

우선순위는 예상 가치 개선, 통제 가능성, 실행 가능성, 비용과 기간을 함께 평가하여 결정합니다.

### 5.11.2 살아 있는 리포트 — 조기경보 체계

교통과 도시계획은 지속적으로 변동하므로, 분석을 일회성 PDF로 종료하지 않습니다. 계약된 모니터링 범위 내에서 변동 신호를 조기경보 항목으로 정의하여 추적하며, 주간 상시 모니터링(12.4)에 연결합니다.

**[표 5-25] 조기경보 추적 항목**

| 신호 유형 | 추적 항목 | 변경 시 갱신 대상 |
|-----------|-----------|-------------------|
| 개발계획 변동 | 신규 고시, 계획 변경, 예산 편성·삭감, 입찰·낙찰, 보상, 환경평가, 착공·공정, 준공·개통, 지연·취소 | 성숙도 판정, 시나리오, 촉매카드 |
| 시장 신호 변동 | 거래량 급감, 취소 거래 증가, 전세가 하락, 미분양 증가, 매물량 급증, 호가-실거래 갭 확대 | 가격 판정, 환금성 평가 |
| 공급 신호 변동 | 경쟁 현장 분양 개시, 인허가·착공 물량 증가 | 확률조정 공급, 판매 시한 판단 |
| 표현 유효성 | 상기 변동이 기존 광고 문구의 근거를 훼손하는지 여부 | **게시 중인 광고 문구의 유효성 재검토** |

유리한 변화만 반영하는 것이 아니라 예산 삭감, 일정 지연, 노선 제외, 공급 증가도 함께 반영합니다. 불리한 변화를 반영하지 않은 광고는 상담·계약 단계에서 신뢰 문제로 되돌아오기 때문입니다.

**경쟁 현장 모니터링.** 경쟁 현장의 분양가·혜택·잔여 세대는 공개 API가 없어 현장 담당자의 주기적 확인에 의존합니다. 수기 수집이라는 이유로 관리가 느슨해지지 않도록, 회차별 스냅숏을 기록하고 변화 감지를 규칙화합니다 — 분양가 2% 이상 변동, 혜택 추가·축소, 잔여 세대 20% 이상 증감이 확인되면 조기경보로 승격되며, 각 신호마다 **어떤 판정을 갱신해야 하는지**가 함께 지정됩니다. 마지막 수집으로부터 30일이 지나면 신선도 경고가 발생해 방치를 막습니다.

한 회차만 있으면 "변화 없음"이 아니라 **"비교 불가"**입니다. 회차 간 현장명이 일치하지 않아 짝지어지지 않는 경우도 같은 방식으로 표기됩니다.

### 5.11.3 현장 반응 피드백 — 분석을 검증하는 역방향 경로

조기경보가 외부 데이터의 변동을 추적한다면, 현장 반응 피드백은 **내부 데이터 — 상담·거절 기록 — 로 분석 자체를 검증**하는 경로입니다. 이 데이터는 외부에서 구매할 수 없는 당사 운영체계 고유의 검증 자산입니다.

**[표 5-26] 현장 반응과 분석 판정의 정합성 점검**

| 현장 신호 (제9~10장에서 축적) | 검증 대상 분석 판정 | 어긋날 경우의 조치 |
|-------------------------------|---------------------|---------------------|
| 가격 거절 사유의 비중과 내용 | 판정 ① 현재 가격 위치 | 가격 갭 재산정, 총취득원가·실부담 설명 점검 |
| 상담 고객의 거주지·직장 분포 | 판정 ② 수요 지속성 (타깃 생활권 가설) | 수요 레이어 가중치·타깃 지역 재검토 |
| 경쟁 현장 이탈 사유 | 판정 ③ 공급·환금성 위험 | 경쟁 물량 평가·비교 논리 갱신 |
| 호재 관련 질문·불신 반응 | 판정 ④ 촉매 평가와 표현 등급 | 촉매카드 보강 또는 해당 문구 등급 하향 |

월 단위로 "모델 판정 대 현장 반응"의 정합성을 점검하고, 어긋나는 항목은 재검토 대상으로 지정합니다. 분석이 현장을 가르치기만 하는 것이 아니라 **현장이 분석을 교정하는 양방향 구조** — 이것이 폐쇄형 학습(4.4)의 분석 측 구현입니다.

## 5.12 소결

현장분석은 전통적 광고대행의 업무 흐름에는 존재하지 않는, 본 운영체계의 첫 번째 단계입니다.

본 장의 프레임워크는 **"무엇을 근거로 팔 것인가"를 계약 전에 검증 가능한 형태로 확정**합니다. 데이터 목록은 모방될 수 있으나, 독립 검증·반증·신뢰도 표시라는 방법론의 규율이 분석 품질을 결정합니다.

그리고 본 장에 기술된 것은 **설계도가 아니라 이미 작동하는 소프트웨어**입니다. 15개 레이어 중 13개가 연동되어 있고, 조정계수 교정·백테스트·근거원장·예측 이력 장부가 실행 가능한 명령으로 존재합니다. 무엇이 구현되었고 무엇이 아직 아닌지는 부록 F에 그대로 적었습니다 — 제안서가 스스로에게 적용하지 않는 규율을 분석에만 요구할 수는 없기 때문입니다.

이 분석 결과가 영업 언어로 전환되는 절차가 제6장의 주제입니다.

# 제6장. 판매 논리 설계

**헤드라인.** 분석과 영업 사이에 판매 논리 설계 단계를 두어, 광고·정보 허브·상담이 동일한 근거로 말하게 합니다.

**[표 6-1] 장 요약**

| 구분 | 내용 |
|------|------|
| 문제 (Problem) | 분석 품질이 높아도 채널·상담원마다 설명이 다르면 상담 단계에서 신뢰가 훼손된다 |
| 원인 (Reason) | 분석 결과를 영업 언어로 변환하고 통제하는 표준 단계가 존재하지 않기 때문이다 |
| 방법 (Method) | 고객 질문 6축 메시지맵(6.2), 상담 조직용 근거팩(6.3), 문장별 표현 등급 지정(6.4)을 설계 산출물로 확정한다 |
| 기대 효과 (Effect) | 채널 간 메시지 불일치가 차단되고, 고객의 반론이 설계 단계에서 먼저 검증된다 |

## 6.1 설계 원칙

판매 논리 설계는 전통적 대행 구조에 존재하지 않는 단계입니다. 대행 구조에서는 분석 없이 광고 문구가 작성되므로, 문구는 혜택·입지·마감의 반복으로 수렴합니다(제3장). 본 체계에서는 광고 집행 전에 이 단계가 반드시 선행됩니다.

**[표 6-2] 판매 논리의 세 가지 설계 원칙**

| 원칙 | 내용 |
|------|------|
| 질문 대응 | 장점을 나열하지 않고, 고객이 실제로 묻는 질문에 근거와 비교로 답한다 |
| 반대근거 병기 | 유리한 근거만이 아니라 5.4.4에서 탐색된 반대근거를 함께 배치한다 |
| 사용 통제 | 모든 문장에 광고 사용 등급을 지정하여, 검증되지 않은 표현의 유입을 차단한다 |

두 번째 원칙은 윤리 이전에 전환율의 문제입니다. 광고에서 과장된 기대를 형성한 고객은 상담 단계에서 이탈하고, 광고에서 검증된 기준을 확인한 고객은 상담을 신뢰 위에서 시작합니다. **판매 논리가 상담 단계에서 유지되려면, 설계 단계에서 반론을 먼저 통과해야 합니다.**

## 6.2 고객 질문 6축 메시지맵

**[표 6-3] 고객 질문과 분석 근거의 대응**

| 고객 질문 | 분석 근거 (제5장) | 설득 방향 |
|-----------|-------------------|-----------|
| 분양가가 비싼 것 아닌가? | 총취득원가·비교단지·품질조정 가격 (5.5) | "같은 가격"이 아니라 "같은 조건"으로 비교 |
| 입주 시점에도 수요가 있는가? | 상주·근무·이동 수요, 청약·전세 (C1·C2·C3·C5) | 어떤 고객층이 왜 필요한지를 데이터로 설명 |
| 공급이 많아지지 않는가? | 입주예정·착공·미분양·확률조정 공급 (C6) | 공급 위험과 흡수 조건을 함께 제시 |
| 교통호재가 실제로 되는가? | 성숙도 단계·예산·계약·시간 변화 (5.6) | 추진 단계와 현장 효과를 분리하여 제시 |
| 나중에 팔 수 있는가? | 거래량·회전율·전세·매도 소요기간 (L11) | 환금성의 근거와 제약을 함께 설명 |
| 왜 지금 검토해야 하는가? | 분양조건·시장 위치·공급 일정·촉매 상태 | 과장된 긴급성 대신 확인 가능한 판단 시점 제시 |

일곱 번째 축은 운영 중에 생성됩니다. **상담 거절 사유**입니다. "다른 고객은 무엇을 우려했는가"를 분석하여 FAQ·후속 메시지·리타기팅 논리로 전환합니다(제10장).

판매 논리의 원천은 착수 시점의 분석만이 아니라, **운영 중 축적되는 현장의 실제 반응**입니다.

## 6.3 상담 조직을 위한 산출물

판매 논리는 광고만이 아니라 상담 현장을 위해 설계됩니다.

**[표 6-4] 영업 지원 산출물**

| 산출물 | 내용 | 사용 주체 |
|--------|------|-----------|
| 고객용 요약 리포트 | 진단 결과를 고객이 이해할 수 있는 형태로 정리한 근거카드 모음 | 상담 시 고객 제시 |
| 상담 근거팩 | 질문 축별 표준 답변, 비교표, 근거 출처 | 상담원 |
| 거절 대응 자료 | 빈출 거절 사유(가격·대출·가족 협의·경쟁 현장)별 사실 기반 대응 논리 | 상담원 |
| 메시지맵 | 고객 유형·질문·근거·표현등급의 대응표 | 광고·허브·상담의 공통 기준 |

상담원마다 조건 안내가 다른 현장은 신뢰를 즉시 상실합니다. 분양조건과 표현의 단일 기준은 시행사 승인으로 확정되며, **조건 변경 시 광고·정보 허브·상담자료가 동시에 갱신**됩니다.

**생성 방식.** 위 산출물은 분석 결과에서 **직접 생성**됩니다. 사람이 리포트를 읽고 옮겨 적는 방식이 아니므로, 리포트의 수치가 갱신되면 상담 자료도 같은 근거로 함께 갱신되며 둘이 어긋날 경로가 없습니다. 생성된 모든 문장은 표현 린트(6.4)를 통과해야 하고, 차단된 문장은 산출물에 실리지 않습니다.

**[표 6-4-1] 질문 축별 답변 생성 조건**

| 축 | 답변이 생성되는 조건 | 조건 미충족 시 |
|----|---------------------|----------------|
| Q1 분양가 | 품질조정 밴드가 산출됨 | "비교 표본 부족" |
| Q2 수요 | 수요 레이어 또는 실부담·청약 중 하나 이상 산출됨 | "수요 레이어 미수집" |
| Q3 공급 | 공급 목록과 현장 세대수 입력됨 | "공급 목록 미입력" |
| Q4 호재 | 등록 계획 중 **검토 단계를 넘은 것이 하나 이상** 존재 | "모두 검토 단계로 확정적 언급 불가" |
| Q5 환금성 | 회전율 산출됨 (비교단지 세대수 필요) | "회전율 미산출" |
| Q6 시점 | 공급·계획·경보 중 하나 이상의 신호 존재 | "판단 시점을 지지할 근거 없음" |

**답하지 않는 것이 설계의 핵심입니다.** 근거가 산출되지 않은 축에서 그럴듯한 문장을 만들어 내면, 상담원은 근거 없는 말을 손에 쥔 채 고객을 만나게 됩니다. 그 축은 답변 대신 **"확인 후 회신"** 원칙이 지정되며, 근거가 확보되면 재생성됩니다.

같은 규율이 거절 대응에도 적용됩니다. 예컨대 가격 거절에 대한 대응 논리는 Q1의 근거에 기대므로, Q1이 답변 불가 상태라면 대응 문구도 "사실 기반 대응 불가 — 확인 후 회신"으로 낮춰집니다. 근거 없는 방어 논리를 상담원에게 주지 않기 위해서입니다.

**근거가 있어도 단정할 수 없는 경우가 있습니다.** 강건성 검사(5.8.1)에서 해당 축의 판정이 가정 하나로 뒤집힌다고 확인되면, 답변은 생성되되 **단정형 사용이 차단**되고 "현재 가정 기준"이라는 조건이 병기됩니다. 상담 자료에는 어느 가정이 결론을 좌우하는지가 그대로 적힙니다 — 예: "① 가격 위치 판정은 연식 조정계수 가정이 바뀌면 방향이 뒤집힙니다. 확언 대신 조건과 함께 제시." 분석이 스스로 불확실하다고 밝힌 결론을 상담 조직이 확언으로 사용하는 것은, 근거 없는 문장을 쓰는 것과 같은 종류의 위험이기 때문입니다.

## 6.4 표현 통제와의 연결

메시지맵의 모든 문장에는 광고 사용 등급(사용 가능·조건부 사용·사용 금지)이 지정됩니다.

등급의 판정 기준과 검수 체크리스트는 제14장 14.5에서 단일 기준으로 정의하며, 광고 표현의 최종 승인권은 시행사가 보유합니다. 이로써 "영업 현장에서 무엇을 말해도 되는가"가 개인의 판단이 아닌 문서화된 기준이 되고, 검증되지 않은 문장이 광고와 상담에 유입되는 경로가 설계 단계에서 차단됩니다.

## 6.5 소결

판매 논리 설계는 분석(제5장)과 실행(제7~9장)을 연결하는 통제 지점입니다.

이 단계를 통과한 문장만 콘텐츠 제작과 상담에 사용되며, 운영 중 축적되는 거절 사유(제10장)가 이 단계로 환류되어 논리가 갱신됩니다. 확정된 판매 논리가 어떤 형태로 고객에게 전달되는지가 제7장의 주제입니다.

# 제7장. 콘텐츠 전략

**헤드라인.** 콘텐츠는 혜택의 확대가 아니라 고객 질문의 해소를 기준으로 제작합니다.

**[표 7-1] 장 요약**

| 구분 | 내용 |
|------|------|
| 문제 (Problem) | 범용 이미지·이벤트 중심 콘텐츠는 검토 단계 고객의 질문에 답하지 못한다 |
| 원인 (Reason) | 콘텐츠가 분석·판매 논리와 분리되어 제작되기 때문이다 |
| 방법 (Method) | 질문형 콘텐츠 설계(7.1)와 GEO 현장 정보 허브(7.2)로 광고·리포트·상담이 동일한 근거를 참조하게 한다 |
| 기대 효과 (Effect) | 클릭 후 이탈이 감소하고, 채널 간 메시지 불일치와 설명 누락이 구조적으로 감소한다 |

|------|------|
| 근거의 단일화 | 광고·리포트·상담이 동일한 근거 페이지를 참조하므로 메시지 불일치와 설명 누락이 구조적으로 감소 |
| 정보 구조의 개선 | 검색엔진과 생성형 AI가 현장 정보를 이해·인용하기 쉬운 구조를 갖추어, 고객의 능동적 탐색 경로에서 정확한 정보로 발견되게 함 |

*유의사항: 생성형 AI의 인용·노출은 외부 플랫폼의 정책과 모델에 따라 결정되며, 당사는 이를 보장하지 않습니다. GEO는 "AI 추천을 보장하는 활동"이 아니라 정보의 구조·출처·접근성을 개선하는 활동입니다.*

## 7.3 제작 범위와 비용 구분

**[표 7-6] 운영 포함 항목과 별도 견적 항목**

| 구분 | 항목 |
|------|------|
| 운영에 포함 | 콘텐츠 방향 설계(질문·콘셉트·매체별 활용안, 초기 3~5개 방향), 소재 운영·테스트, 분석 기반 문안의 근거 검수 |
| 별도 견적 | 이미지 광고 소재, 영상 콘텐츠·편집, 현장·모델·드론 촬영, 리포트 디자인, 정보 허브 제작, 추가 디자인·인쇄물 |

별도 제작은 품목·수량·수정 횟수·납기·저작권 범위를 견적서로 사전 승인받은 후 착수하며, "콘텐츠 일체"와 같은 범위 불명확한 표현은 사용하지 않습니다. 비용 분리의 원칙은 제11장 11.3에서, 계약 시 확정 항목은 제13장 13.4에서 각각 정의합니다.

## 7.4 소결

콘텐츠의 품질 기준은 시각적 완성도 이전에 근거 정합성입니다.

모든 콘텐츠는 판매 논리(제6장)의 표현 등급을 통과한 문장으로 제작됩니다. 이 콘텐츠가 어떤 매체에서 어떤 역할로 노출되는지가 제8장의 주제입니다.

---

# 제8장. 광고 운영

**헤드라인.** 매체는 나열하지 않고, 고객 여정 단계별 역할로 분담하여 운영합니다.

**[표 8-1] 장 요약**

| 구분 | 내용 |
|------|------|
| 문제 (Problem) | 매체별 개별 운영은 평가 기준의 혼동(단일 DB 단가 일괄 평가)과 증빙 편향(특정 매체 집중)을 유발한다 |
| 원인 (Reason) | 매체마다 고객 여정에서 담당하는 역할이 다른데, 역할 구분 없이 동일한 지표로 평가되기 때문이다 |
| 방법 (Method) | 단계별 역할 분담(8.1), 매체별 공개 항목 표준화(8.2), 후속 매체 운영 원칙(8.3), 집행 전 검수(8.4)를 적용한다 |
| 기대 효과 (Effect) | 각 매체가 담당 역할의 지표로 평가되고, 모든 유입이 캠페인·소재 단위로 계약까지 추적된다 |

## 8.1 고객 단계별 매체 역할

**[표 8-2] 고객 여정과 매체 역할 분담**

| 고객 단계 | 주요 매체 | 역할 |
|-----------|-----------|------|
| 신규 관심 형성 | Meta·Instagram·Demand Gen | 가격·비교·질문형 콘텐츠로 잠재 수요 발굴 |
| 영상 신뢰 형성 | YouTube·Shorts·Reels | 현장과 분석 근거의 시각적 전달 |
| 적극 검색 수요 | Google 검색광고 | 현장명·지역·가격·비교·청약 등 명시적 수요 포착 |
| 상담 전환 확대 | Performance Max | 사이트 행동·전화·상담 신청의 통합 최적화 |
| 기존 DB 재접촉 | LMS | 상담 상태와 관심 주제에 맞춘 후속 정보 제공 |
| 정보 확인 | GEO 정보 허브 | 광고와 상담의 공통 근거 허브 (제7장) |
| 방문·상담 관리 | 분양 업무툴 | 담당자·연락·감도·일정·계약 상태 관리 (제9장) |

역할 분담의 실익은 **평가 기준의 정확성**입니다. 각 매체가 담당 역할의 지표로 평가되므로, 단일 DB 단가로 전체 매체를 일괄 평가하는 오류(3.4)가 발생하지 않습니다.

## 8.2 매체별 운영·공개 항목

**[표 8-3] 매체별 목적과 확인 지표**

| 매체 | 주요 목적 | 확인 지표 |
|------|-----------|-----------|
| Meta | 관심 형성·리드·리타기팅 | 캠페인·광고세트·소재·지출·노출·클릭·리드·리드당 비용 |
| Google 검색 | 명시적 지역·현장·가격 수요 포착 | 검색어·클릭·전화·상담·전환·비용 |
| Performance Max | 여러 Google 지면의 전환 확대 | 자산그룹·지출·전환·전화·상담·가치 |
| Demand Gen | 발견형 시각 콘텐츠로 관심 확대 | 소재·노출·클릭·사이트 행동·리드 |
| YouTube | 영상 신뢰와 재접촉 풀 확보 | 조회·시청시간·사이트 유입·보조 전환 |
| LMS | 기존 DB의 상태별 후속 접촉 | 대상·발송·성공·클릭·상담 연결·방문 전환 |

공통으로 기간·일별 비용·전환 정의·어트리뷰션·계정 화면(또는 리포트)이 공개됩니다. 유입 추적 체계(UTM·리드 ID)는 업무툴까지 보존되어 소재별 계약 기여 분석의 기반이 됩니다.

## 8.3 LMS 운영 원칙

LMS는 발송 건수와 단가의 확인이 용이하여 증빙 편향(2.5)이 발생하기 쉬운 매체입니다. 당사의 원칙은 다음과 같습니다.

> **신규 수요 확보는 발견·검색·영상 매체가 담당하고, LMS는 이미 수집된 고객을 상담 상태와 관심 주제에 맞춰 재접촉하는 후속 매체로만 사용합니다.**

**[표 8-4] 상담 상태별 후속 메시지 설계**

| 고객 상태 | 메시지 목적 | 내용 |
|-----------|-------------|------|
| 미연락·연락 실패 | 재접촉 경로 확보 | 통화 가능 시간 선택, 간단 자료 확인 링크 |
| 가격 관심 | 총비용과 비교 기준 제시 | 분양가·옵션·세금·비교단지 요약 |
| 교통 관심 | 현재와 계획의 분리 | 현재 이동시간, 공식 추진 단계, 조건부 개선 |
| 고감도·방문 전 | 불확실성 해소 | 방문 체크포인트, 세대·주차·상담 준비자료 |
| 방문 후 미결정 | 거절 사유별 보완 | 가격·대출·가족 협의·경쟁 현장 비교자료 |
| 장기 보류 | 과도한 반복 회피 | 분양조건·공정·공식 계획의 실질 변경사항만 발송 |

발송은 수신 동의 범위와 광고성 정보 표시 기준을 준수하며(제14장), 발송 건수가 아니라 **상담 연결·방문 전환**으로 평가됩니다.

## 8.4 집행 전 검수와 운영 통제

**[표 8-5] 캠페인 개시 전 검수 항목**

| 영역 | 검수 내용 |
|------|-----------|
| 광고계정 | 소유·권한·결제·전환 설정·명명 규칙 |
| 유입 추적 | 전환 이벤트 정의, 중복 제거, 업무툴 연동 |
| 표현 승인 | 제6장 등급 지정 완료 및 시행사 승인 |

운영 중에는 예산 이상·급격한 소진·미집행이 알림으로 관리되고, 매체·소재·타깃의 조정은 주간 운영 사이클(제12장)의 승인 절차를 따릅니다. 근거 미확정 문구의 광고 사용 금지 원칙(12.1)은 집행 기간 전체에 적용됩니다.

## 8.5 소결

전통적 대행 구조에서 광고 집행은 업무의 전부이지만, 본 운영체계에서는 열 단계 중 네 번째 단계입니다. 광고 앞의 세 단계가 집행의 품질을 결정하고, 광고 뒤의 여섯 단계가 집행의 성과를 회수합니다.

매체 운영의 최종 평가는 매체 내부 지표가 아니라 업무툴로 이어지는 전환 데이터로 수행됩니다. 그 관리 체계가 제9장의 주제입니다.

---

# 제9장. CRM·고객관리

**헤드라인.** DB 전달은 운영의 종료가 아니라 전환관리의 시작입니다.

**[표 9-1] 장 요약**

| 구분 | 내용 |
|------|------|
| 문제 (Problem) | DB를 다수 확보해도 최초 연락 지연·배정 불명확·후속 부재로 전환 기회가 소멸한다 |
| 원인 (Reason) | DB 처리 상태가 담당자 개인에게 귀속되어 관리 사각지대가 발생하기 때문이다 |
| 방법 (Method) | 10단계 표준 고객 상태(9.2), 규칙 기반 배정과 연락 지연 알림(9.3), 관리자 대시보드(9.4)를 운영한다 |
| 기대 효과 (Effect) | 본부가 별도 보고 없이 병목을 상시 확인하고, 거절 사유가 조직의 데이터로 축적된다 |

## 9.1 두 구조가 갈라지는 지점

**[그림 9-1] DB 전달 지점에서의 구조 분기**

```
전통적 대행:  광고 집행 → DB 수집 → DB 전달 → 종료
                                      │
분양하마:                             └→ CRM 연동 → 고객관리 → 방문 → 계약 → 학습 → 최적화
```

광고의 책임이 DB 전달에서 종료되는 구조에서는, 그 이후의 모든 손실(연락 누락, 배정 불명확, 후속 부재)이 관리 사각지대에서 발생합니다.

당사는 DB 전달을 **전환관리의 시작**으로 정의합니다. 광고·정보 허브·전화·LMS에서 유입된 DB는 업무툴에 자동(또는 규칙 기반) 연동되며, 유입 시각·캠페인·소재·동의 정보가 보존된 상태로 담당자에게 배정됩니다. 중복 DB는 식별·병합되고 연락처는 정규화됩니다.

## 9.2 표준 고객 상태 10단계

고객의 상태는 담당자의 기억이 아니라 표준 단계로 관리됩니다.

**[표 9-2] 고객 퍼널 10단계와 필수 기록**

| 단계 | 정의 | 필수 기록 |
|------|------|-----------|
| 1. 신규 DB | 광고·전화·LMS·현장 등에서 신규 유입 | 유입 시각·캠페인·소재·동의 정보 |
| 2. 미연락 | 담당자 배정 후 연락 시도 없음 | 담당자·배정 시각·기준시간 |
| 3. 연락 시도 | 전화·문자 등 접촉 시도 | 시도 시각·채널·결과·다음 연락 |
| 4. 상담 완료 | 기본 니즈·예산·관심 주제 확인 | 상담 요약·거절 요인·고객 감도 |
| 5. 고감도 | 방문 또는 구체 조건 검토 가능성 높음 | 판정 사유·후속 일정·필요 자료 |
| 6. 방문 예정 | 일정과 참여자 합의 완료 | 일시·인원·담당자·확인사항 |
| 7. 방문 완료 | 현장·모델하우스 상담 완료 | 방문 결과·관심 호수·보완 과제 |
| 8. 계약 검토 | 청약·가계약·자금계획 등 구체 검토 | 의사결정자·자금·기한·쟁점 |
| 9. 계약 완료 | 계약 기준 충족 및 등록 | 계약일·상품·금액·기여 경로 |
| 10. 보류·거절 | 전환 중단 또는 장기 검토 | 표준 사유·메모·재접촉 가능일 |

10단계의 **표준 사유** 기록이 학습 구조(4.4)의 원료입니다. 가격·대출·가족 협의·경쟁 현장·일정 등 표준 항목으로 기록된 거절 사유는 개인의 인상이 아니라 조직의 데이터가 되어 다음 콘텐츠와 상담 전략에 반영됩니다.

## 9.3 배정·연락지연·후속 관리

**배정.** 팀·담당자·근무 상태·순번·캠페인에 따른 규칙 기반 배정을 적용합니다. 신규 DB는 실시간으로 담당자에게 알림되며 배정 이력이 저장됩니다.

**연락지연 관리.** 최초 연락 기준시간은 현장 근무 체계와 고객 유입 시간을 고려하여 계약 시 확정합니다. 기준 초과 시 담당자와 관리자에게 단계별 알림이 발송되고, 재배정 또는 관리자 개입 규칙을 설정할 수 있습니다.

**[표 9-3] 연락 및 후속관리 기준 (예시)**

| 관리 항목 | 기준 | 관리 조치 |
|-----------|------|-----------|
| 최초 배정 | 유입 즉시 또는 규칙 실행 후 | 담당자 알림, 배정 이력 저장 |
| 최초 연락 | 현장 합의 시간 이내 | 지연 알림, 관리자 대시보드 표시 |
| 연락 실패 | 표준 횟수·시간대별 시도 | 다음 연락 예약, 후속 메시지 보조 |
| 고감도 고객 | 일반 고객보다 단축된 후속 시간 | 관리자 알림, 방문 자료 자동 준비 |
| 방문 예정 | 전일·당일 확인 | 참석 확인, 노쇼 사유, 재예약 |

*상기 시간과 횟수는 확정 SLA가 아니며, 현장 근무시간·인력·유입량을 반영하여 계약 또는 운영계획에서 확정합니다.*

기록 대상은 "연락했음"의 체크가 아니라 **시도 횟수·연결 여부·다음 행동**입니다.

**[표 9-4] 관리자 화면의 고객 상태 표시 (예시)**

| 고객 | 유입 소재 | 담당자 | 현재 상태 | 후속 조치 | 지연 여부 |
|------|-----------|--------|-----------|-----------|-----------|
| A | 가격 비교형 | 담당 1 | 상담 완료 | 방문 일정 확인 | 정상 |
| B | 교통 분석형 | 담당 2 | 미연락 | 즉시 연락 | **지연** |
| C | 공급 리스크형 | 담당 3 | 방문 예정 | 리마인드 발송 | 정상 |
| D | 현장 영상형 | 담당 1 | 계약 검토 | 반론 자료 전달 | 정상 |

"유입 소재" 열이 이 화면의 핵심입니다. 고객 B가 교통 분석형 소재로 유입됐다는 정보가 보존되므로, 담당자는 해당 고객의 관심 축을 파악한 상태로 연락하고, 관리자는 소재별 전환 성과를 계약까지 추적할 수 있습니다. **광고와 상담이 동일한 데이터 위에서 만나는 지점**입니다.

## 9.4 관리자 대시보드

**[표 9-5] 본부장·총괄 확인 정보**

| 영역 | 확인 항목 |
|------|-----------|
| 고객 현황 | 전체·신규·미연락·연락지연·상담완료·고감도·방문예정·방문완료·계약검토·계약완료 |
| 담당자 현황 | 배정 건수, 최초 연락시간, 상담완료율, 방문예약률, 실방문률, 업데이트 지연 |
| 캠페인 현황 | 매체·캠페인·소재별 DB·유효 DB·상담·방문·계약 |
| 병목 현황 | 중복, 연락 실패, 가격 거절, 가족 협의, 대출, 경쟁 현장, 노쇼 |
| 일정 현황 | 오늘·주간 방문, 담당자별 일정, 미확인·재예약 |
| 운영 알림 | 미연락·지연, 장기 미갱신, 고감도 후속 누락, 상태 미입력, 예산 이상 |

대시보드의 의미는 정보량이 아니라 **질문의 즉답성**입니다. "이번 주 방문 몇 건인가", "미연락 고객이 몇 명인가", "어느 소재에서 계약이 발생했는가" 등 별도 보고를 요청해야 답을 얻던 질문이 상시 조회로 전환됩니다.

## 9.5 제공 조건과 운영 전제

업무툴은 광고 운영 현장에 대해 계약된 기간과 범위 안에서 **별도 라이선스비 없이 제공**하는 것을 표준 원칙으로 합니다(현장 1개 기준). 사용자 수, 계정 권한, 장기 보관, 종료 후 내보내기, 외부 CRM 연동, 추가 개발, 지원 범위는 계약 전에 확정합니다. 종료 후 데이터의 반환·삭제·보존은 개인정보 처리위탁 계약과 현장 정책에 따릅니다(제14장).

한 가지 운영 전제를 명시합니다. **현장 담당자가 상담·방문·계약 상태를 입력하지 않으면 광고별 계약 연결 분석은 제한됩니다.** 업무툴은 입력을 간소화하고 누락을 알림으로 관리하지만, 입력 자체를 대신할 수는 없습니다. 이 때문에 착수 시 현장 운영 책임(담당자 입력 의무, 본부 점검 체계)을 역할 분담으로 합의합니다(제14장).

## 9.6 소결

업무툴은 단순 도구가 아니라 운영 계약의 실행 장치입니다.

광고 유입 정보(제8장)와 현장 처리 기록이 이 지점에서 결합되며, 현장의 입력 책임이 이행될 때 광고-계약 연결 분석이 완성됩니다. 그 측정 체계가 제10장의 주제입니다.

# 제10장. 성과 측정

**헤드라인.** 성과는 DB 단가가 아니라 전체 퍼널로, 사전에 합의된 정의로 측정합니다.

**[표 10-1] 장 요약**

| 구분 | 내용 |
|------|------|
| 문제 (Problem) | 지표 정의가 통일되지 않으면 동일한 숫자를 두고 해석이 갈리고, 성과 보고를 검증할 수 없다 |
| 원인 (Reason) | 유효 DB·상담 완료·방문 확인의 기준이 주체마다 다르고, 성과가 단일 DB 단가로 일괄 평가되기 때문이다 |
| 방법 (Method) | KPI 표준 정의의 사전 합의(10.2), 8영역 지표 체계(10.3), 기준선 측정(10.4), 병목 진단 표준(10.5)을 운영한다 |
| 기대 효과 (Effect) | 성과 판정이 원천 데이터로 검증 가능해지고, 병목별 개선이 데이터로 결정된다 |

## 10.1 측정 기본원칙

**[표 10-2] 성과 측정의 네 가지 원칙**

| 원칙 | 내용 |
|------|------|
| 구간 분리 | 착수 전 기준선, 집행 중 선행지표, 현장 전환지표, 최종 결과지표를 구분하여 관리 |
| 정의 고정 | 지표 정의는 착수 시 문서로 확정하며, 변경 시 이력과 소급 재산출을 병기 |
| 원천 검증 | 모든 보고 수치는 고객 DB·집행 내역의 원천 기록으로 소급 검증 가능 |
| 인과 한정 | 가격·시즌·분양조건·현장 인력·경쟁 현장 등 외부 요인이 존재하므로, 광고·분석만의 인과 효과를 단정하지 않음 |

## 10.2 KPI 표준 정의

동일한 숫자를 보기 위해서는 지표의 정의부터 합의해야 합니다.

**[표 10-3] 핵심 KPI의 표준 정의와 확정 사항**

| KPI | 표준 정의 | 계약 전 확정 사항 |
|-----|-----------|-------------------|
| 유효 DB | 중복·허위·연락 불가 등을 제외한, 합의 조건 충족 DB | 제외 기준, 판정 주체 |
| 최초 연락시간 | DB 생성부터 최초 연락 시도까지의 경과 시간 | 근무시간 처리, 재배정 예외 |
| 상담완료율 | 상담 완료 고객 ÷ 유효 DB | "상담 완료" 상태의 정의 |
| 실제방문율 | 실제 방문 고객 ÷ 방문 예약 고객 | 방문 확인 방식 |
| 계약 연결 | 계약 고객과 최초·주요 유입 소재의 연결 | 귀속 기간, 복수 소재 처리 |

## 10.3 8영역 지표 체계

**[표 10-4] 영역별 핵심 지표와 해석**

| 영역 | 핵심 지표 | 해석 |
|------|-----------|------|
| 예산 투명성 | 실집행률, 매체별 사용액, 잔액, 정산 일치율 | 지급 예산이 실제 매체 집행과 일치하는가 |
| 광고 반응 | 노출·클릭·조회·CTR·CPC·사이트 행동 | 소재와 타깃이 관심을 형성하는가 |
| DB 품질 | DB 건수, 중복률, 유효 DB, 유효 DB당 비용 | 연락 가능한 실질 수요가 유입되는가 |
| 처리 품질 | 배정 시간, 최초 연락시간, 미연락·지연률 | 현장이 전환 기회를 놓치지 않는가 |
| 상담 | 연결률, 상담완료율, 고감도율, 거절 사유 분포 | 메시지와 상담이 고객의 문제를 해결하는가 |
| 방문 | 방문예약률, 확인률, 노쇼율, 실방문률 | 관심이 실제 행동으로 이동하는가 |
| 계약 | 계약검토율, 계약률, 계약당 비용, 기여 경로 | 최종 사업 목표에 어느 정도 기여했는가 |
| 학습 | 근거별·소재별·매체별·담당자별 개선 효과 | 재사용 가능한 지식이 축적되는가 |

## 10.4 기준선과 목표 설정

**[표 10-5] 기준선 설정 절차**

| 상황 | 처리 방식 |
|------|-----------|
| 기존 데이터 보유 | 기존 4~12주의 광고비·DB·유효 DB·연락·상담·방문·계약 데이터로 기준선 산정 |
| 기존 데이터 부재 | 초기 운영 2주를 측정 기간으로 설정한 후 목표 확정 |
| 목표 성격 | 절대 보장값이 아닌 **개선 가설**로 설정 |
| 매체별 목표 | 고객 단계와 역할에 맞게 분리 설정. 단일 DB 단가로 일괄 평가하지 않음 |
| 외부 변화 | 예산·분양조건·현장 인력·시즌 등 주요 변화를 변경 원장에 기록하여 성과 해석에 반영 |

## 10.5 퍼널 병목 진단과 개선 판단

퍼널 지표의 가치는 **병목의 위치와 원인을 구분**한다는 데 있습니다.

**[표 10-6] 관찰 결과별 원인 추정과 우선 개선**

| 관찰 결과 | 가능한 원인 | 우선 개선 |
|-----------|------------|-----------|
| 클릭은 높은데 유효 DB가 낮음 | 후킹과 실제 정보의 불일치, 폼 품질 | 메시지 정합성, 질문 항목, 중복 필터 |
| 유효 DB는 높은데 상담완료가 낮음 | 연락 지연, 시간대, 배정 과부하 | 연락 기준시간, 재배정, 후속 메시지 보조 |
| 상담은 높은데 방문이 낮음 | 가격 저항, 가족 협의, 정보 부족 | 비교 자료, 방문 이유 설계, 일정 확인 |
| 방문은 높은데 계약이 낮음 | 상품·가격·자금·경쟁 현장 | 현장 조건·상담·후속 제안 검토 (시행사 협의 안건) |
| DB 단가는 높지만 계약 기여가 큼 | 고의도 검색 수요, 고가 타깃 | DB 단가만으로 감액하지 않고 계약당 비용으로 판단 |
| 후속 발송은 많은데 방문이 낮음 | 대상·시점·메시지의 상태 불일치 | 상담 단계별 세분화, 발송 빈도 조정 |

네 번째 행은 제3장 3.5의 원칙(운영 문제와 조건 문제의 구분)이 실제로 작동하는 지점입니다. 방문까지 도달했으나 계약이 발생하지 않는 병목은 광고로 해결되지 않으며, 당사는 이 경우 판촉 반복 대신 **데이터를 근거로 시행사에 조건 검토를 안건화**합니다.

**기준선 없이는 병목을 지목하지 않습니다.** 전환율 20%가 좋은지 나쁜지는 기준선 없이 말할 수 없습니다. 계약 시 확정한 기준선(10.4)이 입력되기 전에는 단계별 실측 전환율만 제시하고 판정을 유보합니다 — 근거 없는 병목 지목은 잘못된 예산 배분으로 직결되기 때문입니다. 같은 이유로 분모가 최소 표본에 미달하는 단계는 개별적으로 판정을 유보합니다.

병목 추정은 현장 반응과 대조되어 확신 수준이 조정됩니다. 예컨대 상담→방문 병목에 가격 거절 비중이 함께 높으면 추정이 강화되지만, **가격 판정(5.8 ①)이 '긍정'인데 가격 거절이 많다면** 가격 자체보다 총취득원가 설명 방식의 문제일 수 있으므로 그 어긋남을 그대로 표기하고 양쪽을 함께 점검합니다.

**[표 10-7] 거절·이탈 패턴의 운영 반영**

| 관찰 패턴 | 점검 항목 | 다음 운영 반영 |
|-----------|-----------|----------------|
| 가격 거절 | 총취득원가 설명 부족 여부 | 가격 비교 콘텐츠, 상담 순서 개선 |
| 미방문 | 예약 후 신뢰·리마인드 부족 여부 | 후속 콘텐츠, 발송 시점 조정 |
| 연락 지연 | 광고가 아닌 운영 병목으로 분류 | 배정·알림·예외 처리 규칙 개선 |

## 10.6 소결

학습과 최적화는 전통적 대행 구조에 존재하지 않는 마지막 두 단계입니다. DB 전달에서 업무가 종료되는 구조는 결과 데이터를 보유하지 못하므로 학습이 불가능하고, 학습이 없는 구조의 개선은 소재 교체 수준에 머무릅니다.

본 체계에서 측정의 목적은 평가가 아니라 개선입니다. 병목 진단 결과는 주간 운영 사이클(제12장)을 통해 다음 주 운영에 반영되며, 거절 사유 데이터는 판매 논리(제6장)와 콘텐츠(제7장)의 갱신 입력이 됩니다.

이 측정 체계와 짝을 이루는 것이 예산의 투명성이며, 제11장의 주제입니다.

# 제11장. 광고비 투명성

**헤드라인.** 광고비는 견적서가 아니라 실집행 원장으로 증빙합니다.

**[표 11-1] 장 요약**

| 구분 | 내용 |
|------|------|
| 문제 (Problem) | 총액 견적 방식에서는 실제 매체 집행액과 잔액을 확인할 수 없고, 업체 간 동일 조건 비교가 불가능하다 |
| 원인 (Reason) | 수수료·콘텐츠 제작비·매체비가 하나의 금액으로 혼재되기 때문이다 |
| 방법 (Method) | 수수료 10%·실집행 90%·제작비 별도의 분리 구조(11.2~11.3), 지원금의 실집행 등록(11.4), 공개 항목 표준(11.5), 종료 정산(11.6)을 운영한다 |
| 기대 효과 (Effect) | 예산의 사용처와 고객 결과가 연결되어 검증되고, 동일 조건의 업체 비교가 가능해진다 |

## 11.1 투명성의 원칙

당사는 광고비를 수령했다는 사실만 증빙하지 않습니다. 현장이 지급한 금액이 어떤 기준으로 운영수수료와 콘텐츠 제작비로 구분됐고, 실제로 어느 매체·캠페인·소재에 사용됐으며, 얼마가 잔여하는지를 확인 가능하게 관리합니다.

**[표 11-2] 예산 관리 구분**

| 관리 구분 | 내용 |
|-----------|------|
| 전체 운영예산 | 계약 기준 총액 (부담금·지원금 구분 포함) |
| 운영수수료 | 산정 기준과 금액 |
| 실제 매체 집행액 | 매체별 실제 사용 금액, 일별 사용 내역 |
| 잔여 광고비 | 환불·이월·정산 구분 |

**[표 11-3] 확인 수단**

| 수단 | 확인 내용 | 제공 주기 |
|------|-----------|-----------|
| 운영 대시보드 | 예산·실집행·잔액·매체·성과·고객 상태 | 상시 |
| 매체 리포트 | 캠페인·소재·기간·지출·성과 | 주간·월간·종료 |
| 광고계정 화면 | 실제 집행·결제·권한·캠페인 설정 | 계정 정책과 계약에 따름 |
| 충전·결제 내역 | 결제일·금액·결제자·환불·크레딧 | 매체 결제 방식에 따름 |
| 종료 정산서 | 계약·수수료·제작비·실집행·잔액 | 종료 시 |

핵심은 **Meta·Google·YouTube·LMS의 집행액을 광고계정·결제·플랫폼 리포트와 대조 검증할 수 있다**는 점입니다. 대시보드 수치는 원천 자료와 대사(對査) 가능해야 하며, 이 대사 가능성 자체가 검수 항목입니다(제13장).

## 11.2 비용 구조

표준 조건은 부가세 제외 광고운영예산의 10%를 운영수수료로, 90%를 실제 매체 집행 예산으로 구분하는 것입니다.

**[표 11-4] 광고운영예산 1,000만원 예시 (부가세 제외, 비용 구조 설명용)**

| 항목 | 금액 | 비율 | 비고 |
|------|------|------|------|
| 전체 광고운영예산 | 10,000,000원 | 100% | |
| 광고 운영수수료 | 1,000,000원 | 10% | 운영 범위는 계약서에 명시 |
| 실제 매체 집행 예산 | 9,000,000원 | 90% | 매체·캠페인별 사용 내역 공개 |
| 콘텐츠 제작비 | 별도 견적 | — | 영상·디자인·리포트·정보 허브 등 |

참고로 동일한 1,000만원 예산에서 수수료가 30%인 구조와 비교하면 실제 매체 집행 가능 금액은 700만원 대 900만원으로 200만원의 차이가 발생합니다. 다만 이 비교는 단순 산술 예시이며, 타사의 제작·운영 범위나 성과를 평가하는 근거로 사용될 수 없습니다. 수수료율은 구조와 함께 비교되어야 합니다(4.6).

*예시는 확정 견적이 아닙니다. 부가세, 최소 운영비, 결제수수료, 외부 솔루션비, 환율·매체 정책은 계약 전에 확정합니다.*

## 11.3 콘텐츠 제작비 분리 원칙

광고 운영비와 콘텐츠 제작비는 원가 구조와 업무 성격이 다르므로 처음부터 분리합니다.

**[표 11-5] 운영수수료와 제작비의 구분**

| 구분 | 광고 운영수수료 (10%) | 별도 콘텐츠 제작비 |
|------|----------------------|-------------------|
| 주요 범위 | 계정·캠페인 세팅, 집행, 최적화, 리포트, 운영 회의 | 영상·촬영·디자인·리포트·정보 허브·3D 등 |
| 산정 방식 | 광고운영예산의 10% | 품목·수량·난이도·수정 횟수·납기별 견적 |
| 승인 방식 | 운영 계약과 예산 승인 | 제작 착수 전 개별 산출내역 승인 |
| 권리·원본 | 광고계정·운영자료 기준 | 소스파일·초상권·음원·사용기간 별도 명시 |
| 추가 비용 | 계약 범위 초과 시 사전 협의 | 추가 촬영·대량 수정·긴급 납기 등 사전 협의 |

이 분리가 발주처를 보호하는 이유는 명확합니다. 제작비가 운영비에 혼재되면 **"실제 광고에 사용된 금액"을 산출할 수 없게 되고**, 그 시점부터 매체 효율의 평가, 업체 간 비교, 정산 검증이 모두 불가능해집니다.

## 11.4 1+1 광고비 지원 구조의 운영

**[표 11-6] 지원 구조 운영 6원칙**

| 원칙 | 내용 |
|------|------|
| ① 별도 등록 | 부담금과 지원금을 구분 등록하여 주체별 기여 예산을 확인 가능하게 함 |
| ② 사전 승인 | 매체별 배분 계획을 사전 승인받고 실제 집행과의 차이를 기록 |
| ③ 실집행 연결 | 지원받은 광고비까지 견적서상 금액으로 남기지 않고 실제 집행 예산으로 등록 |
| ④ 내역 공개 | 일별·캠페인별 사용 내역과 잔여 예산을 확인 가능하게 함 |
| ⑤ 성과 연결 | 지원금으로 유입된 DB도 캠페인·소재와 연결하여 상담·방문·계약 결과를 분석 |
| ⑥ 종료 정산 | 미집행 잔액의 환급·이월·차기 집행을 계약 기준에 따라 정산 |

지원 제도의 취지(현장 참여 촉진)를 유지하는 방법은 통제를 제거하는 것이 아니라 **추적을 가능하게 하는 것**입니다. 지원 주체는 자신의 지원금이 어느 매체에서 어떤 고객을 만들었는지 확인할 수 있어야 합니다.

## 11.5 공개 항목

**[표 11-7] 광고비·성과 공개 항목**

| 구분 | 세부 항목 |
|------|-----------|
| 계약·예산 | 전체 계약 금액, 광고운영예산, 현장 부담금, 지원금, 부가세, 별도 제작비 |
| 수수료 | 광고 운영수수료, 산정 기준, 추가 서비스 비용 |
| 실집행 | 실제 매체 집행 금액, 매체·캠페인·소재·일별 사용 금액, 집행 기간 |
| 잔액·정산 | 충전·결제 내역, 사용액, 잔여 광고비, 종료 후 정산·이월 기준 |
| 광고 성과 | 노출·클릭·조회·전화·상담 신청·DB·DB당 비용 |
| 전환 성과 | 유효 DB·상담 완료·방문 예약·실방문·계약 검토·계약 |
| 운영 품질 | 중복률, 최초 연락시간, 연락 지연, 미처리, 거절 사유 |

마지막 두 행이 본 장의 핵심입니다. 광고비 투명성은 "예산이 어디에 사용됐는가"에서 종료되지 않고 **"그 예산이 어떤 고객 결과를 만들었는가"까지 연결될 때** 완성됩니다.

예산 원장과 고객 원장이 동일한 체계에 존재한다는 것, 이것이 당사가 광고대행이 아니라 운영 시스템인 이유의 재무적 표현입니다.

## 11.7 소결

종료 정산은 서류 절차가 아니라, 발주처가 연장·확대·종료의 의사결정을 데이터 위에서 내리게 하는 최종 산출물입니다.

여기까지가 운영의 내용이며, 이 운영이 90일 동안 어떤 순서와 승인 절차로 진행되는지가 제12장의 주제입니다.

# 제12장. 90일 운영 프로세스

**헤드라인.** 90일은 집행 기간이 아니라, 승인 게이트로 통제되는 학습 구간입니다.

| 구분 | 내용 |
|------|------|
| 문제 (Problem) | 준비 없이 시작한 광고는 추적·표현·운영 기준의 부재로 초기 예산을 소모한다 |
| 원인 (Reason) | 집행 전에 확정해야 할 기준(데이터·분석·추적·운영·예산)이 관행적으로 생략되기 때문이다 |

| 기대 효과 (Effect) | 5주차에 표준 운영이 개시되고, 90일 종료 시 연장·확장 판단의 검증된 근거가 확보된다 |

## 12.2 광고 시작 전 필수 확인

다음 다섯 영역의 기준이 합의되기 전에는 계약된 광고 운영을 시작하지 않습니다.

## 12.3 90일 로드맵

**[표 12-5] 단계별 수행 내용과 승인 게이트**

**[표 12-6] 시점별 발주처 확인 가능 상태**

| 시점 | 확인 가능한 상태 |
|------|------------------|
| 2주차 | 진단 결과와 데이터 커버리지표 수령. 목표·지표 합의 완료 |
| 4주차 | 콘텐츠·정보 허브·추적 체계 검수 완료 |
| 5주차 | 표준 운영 개시. 첫 주간 보고 수령 |
| 8주차 | 초기 채널 효율 데이터 확보. 첫 예산 재배분안 상정 |
| 12주차 | 주간 개선 사이클 안착. 소재별 계약 기여 데이터 축적 |

90일을 **집행 기간이 아니라 학습 구간으로 정의**하는 이유는, 첫 캠페인의 목적이 완성된 정답의 실행이 아니라 기준선 위에서 무엇이 작동하는지를 검증된 속도로 확인하는 데 있기 때문입니다.

| 요일 | 활동 |

## 12.6 소결

일정보다 중요한 것은 게이트입니다. 각 단계의 승인 없이 다음 단계가 시작되지 않으며, 이 통제가 초기 예산의 소모와 기준 없는 집행을 방지합니다.

각 게이트에서 승인되는 산출물의 범위와 검수 기준이 제13장의 주제입니다.

# 제14장. 수행 조직·책임과 위험 통제

**헤드라인.** 책임은 RACI로 분리하고, 위험은 8개 범주로 사전 통제합니다.

**[표 14-1] 장 요약**

| 구분 | 내용 |
|------|------|
| 문제 (Problem) | 책임 소재가 불명확하면 사고의 예방과 발생 시 대응이 모두 지연된다 |
| 원인 (Reason) | 분석·표현·집행·입력·개인정보의 책임 주체가 관행적으로 정의되지 않기 때문이다 |
| 방법 (Method) | 수행 조직과 RACI(14.1~14.2), 8범주 위험통제표(14.3), 개인정보 원칙(14.4), 표현 등급·금지 목록(14.5)을 계약에 반영한다 |
| 기대 효과 (Effect) | 표현·개인정보·성과 왜곡 사고가 절차로 예방되고, 발생 시 대응 경로가 사전에 정의된다 |

## 14.2 역할 분담 (RACI)

**[표 14-3] 업무별 책임 구분**

| 업무 | 시행사 | 현장 총괄 | 분양하마 |
|------|--------|-----------|----------|
| 분양조건·예산 확정 | **최종 책임** | 협의 | 협의 |
| 분석자료 제공·사실 확인 | **최종 책임** | 실행 | 실행 |
| 분석·근거원장 | 협의 | 협의 | **최종 책임** |
| 광고 표현 최종 승인 | **최종 책임** | 협의 | 실행 |
| 콘텐츠 제작 | 승인 | 협의 | **실행 책임** |
| 매체 집행·최적화 | 승인 | 협의 | **실행 책임** |
| DB 연락·상담·상태 갱신 | 승인 | **실행 책임** | 협의·지원 |
| 대시보드·성과 분석 | 협의 | 협의 | **최종 책임** |
| 개인정보 기준·위탁 | **최종 책임** | 실행 | 실행 |
| 종료 정산·인계 | 승인 | 협의 | **실행 책임** |

이 분담이 명시하는 두 가지 사실을 강조합니다.

첫째, **광고 표현의 최종 승인권은 시행사에 있습니다.** 당사는 근거와 표현 등급을 제시하고, 시행사가 판매 주장을 확정합니다.

둘째, **DB 연락·상담·상태 입력의 실행 책임은 현장에 있습니다.** 당사는 이를 시스템과 알림으로 지원하지만 대행하지 않습니다(9.5).

| 회의체 | 주기 | 주요 안건 |
|--------|------|-----------|
| 착수·게이트 회의 | 단계별 | 범위·분석·표현·집행·종료 승인 |
| 주간 운영회의 | 주 1회 | 광고비·DB·상담·방문·계약·개선안 |
| 콘텐츠 검수 | 제작 단계 | 근거·표현·브랜드·권리·납기 |
| 예산 검토 | 주간·월간 | 매체 배분·소진 속도·잔액·지원금 |
| 위험·이슈 회의 | 발생 시 | 개인정보·표현·계정·데이터·민원 |
| 성과 평가 | 월간·종료 | 기준선·KPI·기여·확장·중단 판단 |

의사결정은 이슈·의사결정·변경·예산의 4개 원장에 기록됩니다.

**[표 14-5] 8범주 위험과 통제 방안**

| 성과 왜곡 | DB 수량만 강조, 계약 기여 과대평가 | 퍼널 정의·중복 제거·기준선·기여 한계 표시 (14.6) |

위험 항목은 열거 후 종료되는 목록이 아니라 주간 사이클(12.4)의 상시 모니터링 대상입니다. 발생 시 위험·이슈 회의를 소집하고 처리 결과를 이슈 원장에 기록합니다.

## 14.6 성과 해석의 통제

성과 왜곡의 위험은 외부가 아니라 운영사 자신에게서 발생할 수 있습니다. 당사는 다음을 내부 규정으로 금지합니다.

**[표 14-10] 성과 보고 금지 사항**

| 금지 사항 | 통제 방법 |
|-----------|-----------|
| 기여의 과대평가 | 계약 고객의 유입 경로 연결은 합의된 귀속 기준으로만 판정. 광고 외 요인(가격 조정, 시즌, 현장 인력)의 기여를 광고 성과로 흡수하지 않음 |
| 불리한 수치의 지연 보고 | 나쁜 신호일수록 조기에 보고. 조기 대응의 전제 조건 |
| 지표 정의의 사후 변경 | KPI 정의는 착수 시 문서로 고정(10.2). 변경 시 이력과 소급 재산출 병기 |

수요 부족이 실제 원인인 현장에서는 그 사실을 데이터로 보고하고 조건 재검토를 안건화하는 것이 당사의 역할입니다. **운영이 해결할 수 없는 문제를 운영이 해결할 수 있다고 말하지 않는 것**이 본 제안서 전체의 서술 원칙입니다.

## 14.7 소결

통제의 목적은 형식이 아니라 예방입니다.

금지 항목의 목록과 검수 절차는 계약 문서에 포함되어 발주처의 권리가 되며, 위험 항목은 주간 사이클의 상시 모니터링 대상으로 관리됩니다. 이러한 운영 구조가 만들어내는 변화가 제15장의 주제입니다.

# 제15장. 기대 효과

**헤드라인.** 기대 효과는 확인 방법이 지정된 상태 변화로 서술하며, 보장 수치를 제시하지 않습니다.

**[표 15-1] 장 요약**

| 구분 | 내용 |
|------|------|
| 문제 (Problem) | 근거 없는 기대 수치는 검증이 불가능하고, 제안 전체의 신뢰를 훼손한다 |
| 원인 (Reason) | 성과는 상품·가격·시장 국면·현장 인력 등 외부 요인의 영향을 함께 받기 때문이다 |
| 방법 (Method) | 7개 기대 영역마다 확인 방법을 지정하고(15.1), 이해관계자 관점별 의미를 구분한다(15.2) |
| 기대 효과 (Effect) | "달라졌는가"의 판단 자체가 데이터로 검증 가능해진다 |

## 15.1 기대 효과와 확인 방법

**[표 15-2] 영역별 기대 효과와 검증 수단**

| 기대 영역 | 기대 효과 | 확인 방법 |
|-----------|-----------|-----------|
| 경영 가시성 | 광고비와 고객 상태를 동일 화면에서 확인 | 대시보드, 정산, 주간 보고 |
| 근거 신뢰 | 가격·호재·비교 문구의 출처와 한계를 추적 | 근거원장, 표현 검수 기록 |
| 예산 효율 | 증빙 편향이 아닌 고객 단계별 매체 배분 | 매체별 실집행, 퍼널 비용 |
| 현장 속도 | DB 배정과 연락 지연을 조기에 확인 | 배정·최초 연락시간, 미처리 현황 |
| 상담 품질 | 고객 질문별 근거와 거절 대응 자료의 통일 | 상담완료율, 고감도율, 거절 사유 |
| 방문·계약 학습 | 실제 전환에 기여한 소재·매체·과정 파악 | 기여 경로, 전환 퍼널, 사례 분석 |
| 지식 자산화 | 현장별 분석·콘텐츠·상담 데이터의 축적 | 버전, 표준 템플릿, 학습 원장 |

## 15.2 이해관계자별 의미

**[표 15-3] 관점별 변화**

| 관점 | 변화 내용 |
|------|-----------|
| 시행사 경영진 | 광고비 집행과 분양 성과 사이의 블랙박스가 해소됨. 예산 증액·조건 조정·운영 변경의 의사결정을 데이터 위에서 수행. 부진의 원인이 광고·상담·조건·수요 중 어디에 있는지 구분되어 대응의 정확성과 속도가 개선됨 |
| 현장 본부장·총괄 | 별도 보고 요청 없이 미연락·지연·고감도·방문 일정을 상시 확인. 관리의 초점이 보고 취합에서 병목 해소로 이동. 담당자별 처리 품질이 표준 지표로 비교되어 코칭과 배정 조정의 근거 확보 |
| 광고비 지원 주체 | 지원금의 사용처와 성과가 매체·캠페인·고객 단위로 추적됨. 지원 제도의 통제 문제(2.4)가 해소되고 지원 확대·축소 판단의 근거 확보 |
| 분양 담당자 | 유입 소재와 관심 주제가 보존된 DB를 수령하여 첫 통화의 품질이 개선됨. 표준 근거팩과 거절 대응 자료로 상담의 개인 편차 감소. 가망 없는 응대 시간이 감소하고 고감도 고객에 집중 가능 |
| 대외 보고 (대주단·신탁사) | 분양 전망과 대응 계획을 검증 가능한 데이터에 기반하여 작성 가능 |

## 15.3 성과에 대한 한계

성과 보장 배제의 전제(중요 전제)는 본 장의 기대 효과에 동일하게 적용됩니다.

위 기대 효과는 **운영 구조가 만들어내는 확인 가능한 상태의 변화**이며, 그 상태 위에서 계약 성과의 확률을 높여가는 것이 본 시스템의 작동 방식입니다. 성과는 계약 시 합의한 데이터로 측정합니다(10.2).

## 15.4 소결

보장할 수 없는 것을 보장하지 않는 것이 본 제안의 신뢰 기반입니다.

검증 가능한 상태 변화가 축적될수록 계약 성과의 기대값은 상승하며, 그 축적 과정 전체를 발주처가 데이터로 확인할 수 있습니다.

## 16.1 첫 미팅에서 확인할 사항

**[표 16-2] 첫 미팅 진행 순서**

**당사의 첫 제안.** 현재 현장의 분양가, 주변 실거래, 입주 물량, 청약 결과, 경쟁 현장을 먼저 분석하겠습니다. 분석 결과를 바탕으로 고객이 반응할 광고 질문과 AI 진단리포트 샘플을 제시하겠습니다.

| 3 | 광고·업무 운영 기준 확정 | 예산, 계정, 퍼널 정의, 연락 기준, 개인정보 |

## 16.4 맺음말

분양광고의 성과는 광고 소재를 교체한다고 만들어지지 않습니다. 고객이 현장을 검토할 근거가 있어야 하고, 그 근거가 광고와 상담에서 일관되게 전달되어야 하며, 유입된 고객이 적시에 관리되어야 합니다. 그리고 시행사는 광고비와 고객 결과를 직접 확인할 수 있어야 합니다.

전통적 광고대행의 업무는 광고 집행에서 시작하여 DB 전달에서 종료됩니다. 분양하마의 업무는 현장분석에서 시작하여 계약과 학습을 거쳐 다음 주기의 최적화로 이어집니다.

발주처가 계약하는 것은 광고 서비스가 아니라, **열 단계 전체를 하나의 책임으로 운영하는 체계**입니다.

> **광고비는 투명하게 · 고객관리는 실시간으로 · 콘텐츠는 현장마다 다르게**

| 촉매카드 | 개발 사업의 공식 단계·예산·현장 관련성·반대근거·사용 가능 문장을 정리한 고객용 자료 |
| 청약 수요 전망 | 예상 청약경쟁률을 타입별 구간과 미달 위험 등급으로 제시하는 전망 모듈 (부록 E.1) |
| 구간 적중률 | 예측 구간이 사후 실적을 포함한 비율. 예측 신뢰성의 상시 관리 지표 (부록 E.2) |
| 예측 이력 장부 | 모든 전망 산출을 발행 시점에 봉인 저장하고 실적과 대조하는 검증 기록 (부록 E.3) |
| 전세가율 | 전세 ㎡단가를 매매 ㎡단가로 나눈 비율. 가격 하락 시의 완충 두께로 해석 (5.5) |
| 분양가 전세 충당율 | 총취득원가 중 전세보증금으로 회수 가능한 비율 (5.5) |
| 조정계수 | 비교 거래를 연식·층·거래시점 차이만큼 보정하는 비율. 실거래 회귀로 추정하되 검증 통과 시에만 교체 (5.4.6) |
| 홀드아웃 검증 | 앞 기간으로 추정한 계수를 뒤 기간에 적용해 실제로 개선되는지 확인하는 절차 (5.4.6) |
| 분양가 결정 시뮬레이션 | 후보 가격대별로 밴드 위치·수요·청약·미달 위험을 산출하고 규칙에 따라 권고하는 모듈 (5.5) |
| 미산출 | 표본이 최소 기준에 미달하여 수치를 제시하지 않은 상태. 0이나 공란과 구분하여 표기 (5.4.5) |

## 부록 E. 예측 검증 체계 (Forecast Governance)

본 부록은 제5장의 전망 산출물(가격 시나리오, 청약 수요 전망)이 "검증 가능한 예측"이 되기 위한 기술 명세와 관리 절차를 정의합니다. 원칙은 하나입니다 — **당사의 전망은 발행 후 수정되지 않고, 실적과 대조되어, 그 성적이 발주처에 공개됩니다.**

### E.1 청약 수요 전망 모듈 기술 명세

**[표 E-1] 모듈 구성 명세**

| 구성 | 명세 |
|------|------|
| 학습 데이터 | 시장권 청약 이력(청약홈 공개 데이터): 타입별 경쟁률, 순위 내 마감 여부, 미달, 가점 커트라인, 무순위 전환 이력 |
| 입력 피처 | 품질조정 가격 갭(분양가 대비 주변 시세, 5.5), 동시 분양·입주 파이프라인(L13), 수요 기반(C1·C2), 미분양 재고·소진 속도(L12), 청약 제도(규제지역·전매·가점제 비중), 세대수·타입 구성, 브랜드 등급 |
| 산출 | 전체·타입별 예상 경쟁률 구간, 미달 위험 등급, 결과를 좌우하는 상위 민감 변수 |
| 저장 | 전망 레코드(현장, 타입, 예측 구간, 미달 위험, 모델 버전, 입력 데이터 기준일, 발행 시점)를 예측 이력 장부(E.3)에 봉인 |
| 검증 | 시점 분리 백테스트(미래 정보 누출 방지, 5.4.2) 및 실적 확정 후 자동 대조 |
| 표현 통제 | FORECAST 등급 고정(5.9.1). 조건·범위 없이 단일 수치로 광고·상담에 사용 금지 |

### E.2 예측 구간의 적중률 관리

구간 예측은 산출 방식이 고정되고 사후 성적이 측정될 때만 의미를 갖습니다.

**[표 E-2] 적중률 관리 기준**

| 항목 | 기준 |
|------|------|
| 구간 산출 방식 | 모델별로 단일 방식을 문서로 고정하며, 방식 변경 시 버전과 변경 사유를 기록 |
| 적중률(Coverage) 정의 | 신뢰수준 X%로 발행한 구간이 사후 실적을 포함한 비율. 목표: 명목 수준과의 정합 (예: 80% 구간은 사후적으로 약 80%를 포함해야 함) |
| 산출 주기 | 실적 확정 건 누적 기준으로 분기별 산출, 연 단위 총괄 |
| 기준 미달 시 조치 | ① 구간 폭 재보정 ② 해당 세그먼트의 수치 제시 중단 및 정성 등급 전환(5.4.5) ③ 원인 분석 후 모델 재검토 |
| 보고 | 적중률 성적표를 현장 진단리포트의 모델 검증 면에 병기 |

### E.3 예측 이력 장부

**[표 E-3] 장부 운영 규칙**

| 항목 | 규칙 |
|------|------|
| 봉인 저장 | 모든 FORECAST 산출(가격 시나리오, 청약 전망)은 발행 시점에 전망값·전제·모델 버전·기준일과 함께 저장되며, 발행 후 수정·삭제하지 않음 |
| 실적 대조 | 실적(실거래, 청약 결과) 확정 시 전망 대비 결과를 자동 대조하여 장부에 기록 |
| 성적 공개 | 과거 전망 대비 실적 총괄표를 발주처 요청 시 제공. 신규 제안 시 검증 증빙으로 활용 |
| 열람권 | 계약 발주처는 자기 현장에 관한 전망 이력과 대조 결과의 열람권을 가짐 |
| 불리한 결과의 처리 | 빗나간 전망도 장부에서 제외하지 않음. 원인 분석과 모델 개선 이력을 함께 기록 |

이 장부의 목적은 무결한 예측 성적의 과시가 아닙니다. 전망은 빗나갈 수 있으며, 중요한 것은 **빗나감이 은폐되지 않고 측정·개선된다는 사실을 발주처가 확인할 수 있는 구조**입니다. 이 구조가 본 제안서의 모든 전망 서술(중요 전제, 5.7, 5.9)을 선언이 아닌 검증 가능한 약속으로 만듭니다.

### E.4 봉인의 감사 — "수정하지 않는다"를 검증 가능하게

"발행 후 수정하지 않는다"는 약속은 그 자체가 검증 대상입니다. 규정에 그렇게 적혀 있다는 것과 실제로 수정이 불가능하다는 것은 다른 상태입니다.

**[표 E-4] 장부 감사 절차**

| 점검 | 방법 |
|------|------|
| 봉인 무결성 | 저장된 모든 전망의 본문 해시를 **전수 재계산**하여 저장 시점의 값과 대조. 어긋나면 변조 의심으로 보고 |
| 불변 보장 | 데이터베이스 수준의 수정·삭제 차단 장치가 **선언되어 있는지가 아니라 실제로 작동하는지**를, 수정 시도를 직접 실행해 확인 (시도는 되돌림) |
| 대조 상태 | 전망별 실적 확정 여부와 적중 여부를 함께 보고 |

감사는 발주처가 요청하면 언제든 실행하여 결과를 그대로 제출합니다. 무결성이나 불변 보장 중 하나라도 깨져 있으면 감사는 실패로 종료되며, 그 사실을 숨기지 않습니다.

*동일 분석의 재실행에 대하여.* 같은 입력으로 같은 분석을 다시 실행하면 동일한 전망이 산출됩니다. 이때 새 기록을 추가하지 않고 **기존 봉인을 그대로 참조**합니다 — 같은 내용에 두 개의 장부 항목이 생기면 적중률 통계가 왜곡되기 때문입니다. 구간·모델 버전·기준일 중 하나라도 달라지면 별개의 전망으로 새로 봉인됩니다.

### E.5 조정계수 교정의 검증 기록

5.4.6의 교정 절차는 실행할 때마다 다음을 기록으로 남깁니다. 계수가 바뀌었든 바뀌지 않았든 동일하게 남깁니다.

**[표 E-5] 교정 실행 기록 항목**

| 항목 | 내용 |
|------|------|
| 회귀 결과 | 관측 수, 설명력, 변수별 추정치·표준오차·유의성 |
| 게이트 판정 | 계수별 채택·유지 여부와 그 사유 (표본·유의성·부호·범위 중 무엇에 걸렸는가) |
| 홀드아웃 검증 | 학습·검증 구간의 표본 수, 검증 구간의 조정 후 잔차 분산 변화율, 채택 기준 대비 결과 |
| 적중률 대조 | 기존 계수와 후보 계수의 백테스트 적중률 (안전장치, 채택 기준 아님) |
| 최종 계수 | 채택된 계수 값과 출처 표기 ('초기값(미교정)' 또는 '실데이터 교정값') |

이 기록의 존재 이유는 교정의 성공을 보여주는 것이 아니라, **교정이 기각되었을 때 그 사실이 남게 하는 것**입니다. 기각된 교정이 조용히 사라지면 "계수가 검증되었다"는 인상만 남고 검증의 실질은 사라집니다.

## 부록 F. 구현 현황과 검증 상태

### F.2 아직 확정되지 않은 것

**[표 F-2] 미완료 항목과 해소 조건**

| 항목 | 현재 상태 | 해소 조건 |

| L6 유동인구 · L10 카드소비 | 미연동 | 민간 라이선스 협의 (비용·재배포 조건 확인 선행) |
| 경쟁 현장 자료 | 수집 경로는 구현. 자료 자체는 현장 담당자의 주기적 확인에 의존 | 운영 개시 후 회차 누적 |
| 예측 적중률 | 장부 구조는 작동. 실적 확정 건이 누적되기 전에는 "표본 누적 중"으로 판정 유보 | 실적 10건 이상 누적 |

### F.3 이 부록의 취지

위 표에서 "작동"으로 표기한 항목은 시연 가능하며, "미완료"로 표기한 항목은 계약 시점에 그 상태 그대로 인계됩니다. 제안 단계에서 유리하게 적어 두고 운영 단계에서 달라지는 일을 만들지 않기 위해, **구현되지 않은 것을 구현된 것처럼 쓰지 않았습니다.**

특히 조정계수에 관한 표기는 강조할 필요가 있습니다. 교정 엔진이 있다는 것과 계수가 교정되었다는 것은 다른 상태이며, 리포트는 그 둘을 구분해 표기합니다. 발주처가 첫 리포트에서 "계수는 아직 초기값"이라는 문장을 보게 되는 것은 결함이 아니라 설계된 동작입니다.

같은 이유로 강건성 검사(5.8.1)는 초기 회차일수록 더 중요합니다. 계수가 교정되기 전에는 판정 ①이 가정에 의존할 가능성이 높고, 그 사실을 감추지 않고 리포트 첫 장에 적는 것이 이 시스템이 신뢰를 얻는 방식입니다. 검사 결과가 "가정 의존"으로 나오는 회차는 결론을 서둘러 쓰는 대신 **해당 가정의 실측 교체를 우선 안건으로 올립니다**.
