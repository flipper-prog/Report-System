### 0-1. 접근성 표현 통제 (L8이 광고 심의에 갖는 의미)

'역세권'·'도보 5분'은 분양 광고에서 가장 자주 문제가 되는 표현이다. 본 시스템은
이를 린트(사후 차단)가 아니라 **생성 단계에서** 통제한다. 최근접역이 보행 보정
기준 도보 10분 이내일 때만 '도보 n분' 문장이 만들어지고, 그 밖에는 문장 자체가
생성되지 않으며 리포트에 실측 직선거리와 함께 '역세권 표현 사용 불가'가 기재된다.
현장이 접근성을 주장하려면 좌표가 먼저 그것을 지지해야 한다.

### 0-2. 전세 기반 하방 점검 (L11 완성분이 가격 판정에 갖는 의미)

매매 실거래만으로는 "이 가격이 비싼가"는 답해도 "얼마나 밀릴 수 있는가"는
답할 수 없다. 매매가에는 미래 기대가 섞여 있기 때문이다. 전세가는 실거주
수요가 지금 지불하는 금액이라 기대가 섞이지 않으므로, 전세가율은 가격 하락
시의 완충 두께로 읽는다. 시스템은 이를 판정 ①에 다음과 같이 반영한다.

| 상황 | 처리 |
|------|------|
| 밴드 상단 + 전세가율 55% 미만 | 두 신호가 같은 방향 — 하방 위험 **강도 상향** |
| 밴드 상단 + 전세가율 70% 이상 | 완충이 두터움 — 하방 위험 **강도 하향** |
| 전세 표본 8건 미만 | 수치 미산출, LIMITATION 표기 (판정에 반영하지 않음) |
| 갱신 계약 | 갱신요구권·상한제로 가격 논리가 달라 **분석에서 제외**하고 건수 표기 |

분양가 전세 충당율(총취득원가 중 전세보증금으로 회수 가능한 비율)도 함께
산출되어, 투자 수요의 실제 자금 부담을 근거 있는 수치로 설명할 수 있다.

### 0-3. 조정계수 교정 — 그리고 그 과정에서 드러난 조정식의 결함 3건

품질조정 밴드는 비교 거래를 연식·층 차이만큼 보정해 표준화한다. 그 보정률이
예시값이면 밴드 전체가 예시값 위에 서 있는 셈이다. `calibrate` 는 실거래로
계수를 추정하고, **홀드아웃 검증 구간에서 조정 후 잔차 분산이 실제로 줄어들
때만** 채택한다.

참값을 심은 합성 데이터로 엔진을 검증하는 과정에서, 계수를 정확히 복원했는데도
조정 품질이 오히려 나빠지는 현상이 나타났다. 원인은 계수가 아니라 **조정식
자체**였고, 세 가지 결함이 확인되어 모두 수정했다.

| 결함 | 증상 | 수정 |
|------|------|------|
| 조정식이 선형(`1+r·age`)인데 계수는 로그선형으로 추정 | 계수가 클수록 추정식과 적용식이 어긋남 | 조정을 `exp(r·age)` 로 변경해 추정 형태와 일치시킴 |
| 연식 조정 상한이 고정값(0.20) | 교정된 높은 계수에서 오래된 단지들이 모두 상한에 걸려 서로 구분되지 않음 | 상한을 계수에 비례(기준 30년)시켜, 상한이 외삽 방지 역할만 하도록 함 |
| 연식을 **기준일** 기준으로 측정 | 경과 연수가 연식 조정에 섞여, 같은 단지 안에서도 오래된 거래일수록 조정값이 계통적으로 어긋남 | 연식은 **거래 시점** 기준으로 측정하고, 시간 경과분은 시점수정 계수가 따로 담당 |

수정 후 합성 데이터 기준: 검증 구간 잔차 분산 **-74%**, 백테스트 적중률
52.8% → **50.0%** (명목 50%에 정확히 수렴).

적중률을 채택 기준으로 쓰지 않는 이유도 이 과정에서 분명해졌다. 적중률은 밴드
'폭'의 보정 상태를 재는 지표라, 계수를 바꾸면 밴드와 실현값이 같은 방향으로 함께
움직여 거의 변하지 않는다. 실제로 참값을 복원한 데이터에서도 52%→53%로만
움직였다. 따라서 채택은 잔차 분산으로 판단하고, 적중률은 크게 나빠지지 않았는지
확인하는 안전장치로만 쓴다.

### 0-4. 공급 파이프라인 교차검증 (L13)

공급 목록은 지금까지 설정에 수기로 입력한 값이었다. 확인할 방법이 없으면 공급
판정은 입력한 사람의 주장을 되돌려 주는 것에 지나지 않는다. 주택건설실적을
붙여 두 가지를 한다.

| 역할 | 내용 |
|------|------|
| 선행 신호 | 인허가는 착공·분양의 선행 지표다. 전년 대비 30% 이상 급증하면 공급 부담이 지금 낮더라도 판정 ③을 '긍정'으로 닫지 않는다 |
| 교차검증 | 설정 목록(현장 인근)이 시군구 전체 인허가 실적을 넘어서면 중복 집계·취소 사업 포함을 경고한다. 범위가 다르므로 100% 미만은 정상으로 명시한다 |

## 2. 보완 권고 — 우선순위별

### P0. 즉시 반영 (제안·수주 경쟁력에 직결)

**P0-1. 청약경쟁률 예측 모듈의 정식 스펙 부재**

- **문제**: 경쟁 솔루션은 "적정 분양가 + 예상 청약경쟁률"을 핵심 산출물로 전면에 배치. 현 설계는 청약 데이터를 수요 판정의 입력으로만 사용하고 경쟁률 전망을 독립 산출물로 정의하지 않음.
- **권고 스펙** (제안서 5.5에 반영 완료, 툴 구현 기준):

| 구성 | 스펙 |
|------|------|
| 학습 데이터 | 시장권 청약 이력(청약홈): 경쟁률, 순위 내 마감 여부, 미달, 가점 커트라인, 무순위 전환 |
| 피처 | 품질조정 가격 갭(분양가 vs 주변 시세), 동시 분양·입주 파이프라인, 수요 기반(C1·C2), 미분양 재고·소진 속도, 청약 제도(규제지역·전매·가점제 비중), 세대수·타입 구성, 브랜드 |
| 산출 | 전체·타입별 경쟁률 **구간**, 미달 위험 등급, 상위 민감 변수 |
| 검증 | 시점 분리 백테스트 + **예측 구간의 실적 적중률(coverage) 공개** |
| 통제 | FORECAST 등급 고정. 단일 수치 광고 사용 금지 |

- **구현 위치**: 기존 Phase 2(가격·수요·공급 MVP)의 청약 테이블(subscriptions)을 확장. 신규 테이블 `subscription_forecasts(현장, 타입, 예측구간, 미달확률, 모델버전, 예측시점)` 추가.

**P0-2. 예측 불확실성의 정량화 방법 미정의**

- **문제**: "하방·기준·상방 범위 제시"는 원칙만 있고 구간 산출 방법이 스펙에 없음. 구간이 자의적이면 백테스트 규율 전체가 형해화됨.
- **권고**: 구간 산출 방식을 하나로 고정하고 문서화 — 분위 예측(quantile) 또는 적합도 기반 보정(conformal 방식) 중 택일. 핵심은 **"80% 구간은 사후적으로 실제 약 80%를 포함해야 한다"는 적중률 지표를 모델 KPI로 상시 산출**하는 것. 적중률이 무너지면 구간 폭 자동 확대 또는 정성 등급 전환(기존 규칙과 연결).

**P0-3. 예측 이력 아카이브(봉인 장부) 부재**

- **문제**: "백테스트를 한다"는 주장만으로는 수주 단계에서 검증 불가. 벤치마크 대비 신뢰 확보의 결정적 수단이 빠져 있음.
- **권고**: 모든 FORECAST 산출을 발행 시점에 타임스탬프와 함께 봉인 저장하고, 실적 확정 시 자동 대조하는 **예측 이력 장부**를 운영. 신규 제안 시 "과거 예측 vs 실적" 표를 증빙으로 제시. 기존 원장 체계에 `forecast_ledger` 하나를 추가하면 되는 저비용·고효과 항목.

### P1. 단기 보완 (90일 내)

**P1-1. 분양권·입주권 거래 레이어 누락**

- **문제**: 신축 분양 현장의 가장 직접적인 비교 대상은 구축 아파트가 아니라 **인근 분양권 실거래(전매)와 무순위 공급 결과**. 현 데이터 소스 범주(A.6)에 명시돼 있지 않음.
- **권고**: L11에 분양권/입주권 실거래·프리미엄 추이를 추가하고, 품질조정 비교단지 선정 시 분양권을 우선 비교군으로 규칙화.

**P1-2. 매물량·호가 등 선행 신호 레이어 약함**

- **문제**: 실거래는 후행 지표. 매물 증감·호가-실거래 갭은 시장 전환의 선행 신호인데 "민간 매물"이 별도 협의 항목으로만 존재.
- **권고**: 공공 대체(부동산원·KB 매물/시세 통계)를 기본 레이어로 편입하고, 조기경보 체계(제안서 5.11.2)의 "시장 신호 변동" 입력으로 연결.

**P1-3. 현장 데이터의 역방향 피드백 파이프라인 미설계**

- **문제**: 설계가 분석→광고 방향 위주. 상담 거절 사유(예: "가격 저항")가 가격 모델·수요 판정의 검증 신호로 되돌아오는 경로가 스키마에 없음. 이것이 자사 고유 데이터 해자(垓字)가 될 수 있는 지점.
- **권고**: claims 원장에 `field_feedback`(거절 사유 집계, 상담 반응)을 연결하고, 월간 단위로 "모델 판정 vs 현장 반응" 정합성 리포트를 자동 생성. 현장 반응과 모델이 어긋나는 항목을 재검토 큐로.

**P1-4. 실부담 시뮬레이션 범위 협소**

- **문제**: 총취득원가는 구매 시점 비용만 산출. 고객의 실제 질문은 "얼마 있으면 사서 버틸 수 있나" — 대출 규제(LTV·DSR), 중도금 조건, 보유 단계 비용(재산세 등)까지 포함.
- **권고**: 총취득원가 모듈을 "실부담 시뮬레이터"로 확장 — 자기자본 요구액, 월 상환 부담 구간, 금리 시나리오별 변화. L5(소득·구매력)와 결합하면 "이 현장의 구매 가능 가구 수" 추정으로 발전 가능(수요 판정의 강력한 입력).

**P1-5. 세대 단위 밴드와 표본 희소성의 충돌 규칙 미정의**

- **문제**: 타입·층 구간 밴드로 내려갈수록 비교 표본이 급감. 어느 수준까지 세분화를 허용하고 언제 상위 구간으로 롤업할지 규칙이 없음.
- **권고**: 구간별 최소 표본 기준을 정의하고, 미달 시 자동으로 상위 집계(타입→현장)로 롤업하며 리포트에 롤업 사실을 표기. "호 단위 정밀 산출"을 주장하는 경쟁 대비, **정직한 구간 + 명시적 롤업**이 오히려 검증 가능한 차별점.

### P2. 중기 보완 (제품 고도화)

| 항목 | 문제 | 권고 |
|------|------|------|
| P2-1. 모델 드리프트 관리 | 금리 급변 등 국면 전환 시 성능 저하 감지 체계 없음 | 성능 지표 롤링 모니터링, 임계 하회 시 재학습 트리거, 신·구 모델 병행 비교 후 교체 |

| P2-6. 경쟁 현장 모니터링 | 경쟁 분양가·혜택 변경이 MANUAL 수집 의존 | 수집 주기·담당·변경 감지 알림을 운영 규칙으로 정의, 조기경보 항목에 편입 |
| P2-7. 모델 카드 표준화 | 계산원장에 코드 버전은 있으나 모델 단위 문서 표준 없음 | 모델별 1페이지 카드(학습기간·피처·성능·한계·적용 범위) 자동 생성 |

## 3. 벤치마크 대비 종합 판단

| 축 | 시장 벤치마크 | 현 설계 | 판단 |
|----|--------------|---------|------|
| 변수 규모 | 30~250여 개 변수 | 표준 지표 300+ | 동등 이상. 단, 규모보다 커버리지 정직성 유지가 차별점 |
| 산출 정밀도 | 세대(호) 단위 적정가 주장 | 타입·층 구간 밴드 | 표본 기반으로는 구간+롤업이 정직. P1-5 규칙화로 방어 |
| 청약 예측 | 핵심 상품으로 전면 배치 | 미정의 → **P0-1로 신설** | 반영 시 동등 |
| 조기경보 | EWS 상품화 | 살아있는 리포트 + 조기경보 4유형 | 동등. 예측 이력 장부(P0-3) 추가 시 우위 |
| 검증 공개 | 백테스트 언급 수준 | 백테스트 원칙 + 적중률 공개(P0-2) 시 | **우위 확보 가능 지점** |
| 실행 연결 | 리포트/약정에서 종료 | 광고·상담·계약 전환 운영까지 | 구조적 우위 (제안서 4.7) |

**핵심 결론.** 이 툴의 경쟁력은 "더 많은 변수"가 아니라 **검증 가능성**입니다. P0 세 항목(청약 모듈, 구간 적중률, 예측 이력 장부)은 모두 "우리 예측은 사후 검증된다"는 하나의 주장을 완성하는 부품이며, 이 주장은 현재 어떤 벤치마크도 증빙 형태로 제시하지 못하고 있습니다.
